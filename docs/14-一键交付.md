前面 [11](11-上传到GitHub.md) 建仓库、[13](13-只有安卓怎么测.md) 跑 workflow、[05](05-录屏与打包.md) 下录屏，

## 0. 先说清楚：有且只有一件事，脚本替不了你

这一篇里**唯一**需要你手动做的，是给一个 GitHub 令牌。**一次，30 秒，以后永久免。**

**为什么这个不能自动化？** 因为 GitHub 的安全规定不允许任何程序给自己签发凭据。
道理很直白：如果脚本能自动拿到你账号的永久写权限，那么任何一个你从网上
下载下来的脚本都能 —— 那 GitHub 就不用做了。

所以这一步只能你本人在网页上点。**但脚本会把该点的地方直接给你打开、该勾的勾预先选好**，
你只需要点一下 `Generate token`、复制、粘贴。

> 除了这一个，**其余全部自动**。

## 1. 你要做什么（总共三步）

### 第一步：双击 `一键交付.bat`

在项目根目录（`C:\Users\chenj\eclipse-workspace\demo0`）找到它，**双击**。

> 找不到文件扩展名？在文件夹里点「查看」→ 勾上「文件扩展名」。
> 名字里有中文，看着就是「一键交付」。

### 第二步：第一次会弹出一个网页，要你点一下

弹出的页面是 GitHub 的「新建令牌」页。上面已经帮你填好了两处：

| 位置 | 已经是 |
|---|---|
| Note（备注） | `MoneyNote-oneclick` |
| 权限勾选 | ✅ `repo`、✅ `workflow`（往下拉能看到，已经勾好了） |

你要做的：

1. 确认 `repo` 和 `workflow` 这两个**是勾上的**（页面应该已经替你勾了）
2. 点最下面的绿色按钮 **Generate token**
3. 页面顶部出现一串 `ghp_` 开头的字符 —— 点旁边的复制按钮
4. **回到那个黑窗口，粘贴进去，按回车**

> ⚠️ **那串字符只显示这一次。** 刷新页面就再也看不到了（这是 GitHub 故意的）。
> 没复制成功就重新跑一遍脚本，它会再给你打开一次。

粘贴完之后，脚本把它存到 `secrets\token.txt`。
**这个目录已经写进 `.gitignore`，永远不会被提交。**
但它是个明文文件，所以：别发别人、别拷网盘。

### 第三步：等

从这一秒开始，你不需要再点任何东西。

```
[1/6] 检查环境
[2/6] 在 GitHub 上准备仓库
[3/6] 把代码推上去
[4/6] 触发云端的双端构建 + 录屏
[5/6] 下载录屏（iOS 模拟器 / 安卓模拟器）
[6/6] 你现在有了什么
```

**总共约 20~35 分钟，大部分时间是在等云端编译。**
两个工作流在 GitHub 上是**并行**跑的，所以总时间基本等于慢的那个（iOS）。
期间你可以去干别的，但**别关那个窗口**。

### 可选：不改代码也能换仓库名 / 指定后端

脚本支持三个环境变量，都在**同一个命令行窗口**里先 `set` 再跑：

```bat
set GITHUB_REPO=my-money-app
set API_BASE_URL=https://moneynote-api.onrender.com
set GITHUB_TOKEN=ghp_xxxxxxxx
一键交付.bat
```

| 变量 | 作用 |
|---|---|
| `GITHUB_REPO` | 仓库名，默认 `moneynote` |
| `API_BASE_URL` | 编进安卓 APK 的公网后端地址；不设就是模拟器模式 |
| `GITHUB_TOKEN` | 直接给令牌，跳过 `secrets/token.txt`（CI 里用） |

GitHub 用户名**不用设** —— 脚本会用令牌问 GitHub「我是谁」，换账号也不会推错地方。

## 2. 那 20~35 分钟它到底在干什么

很多人会觉得"是不是卡住了"。不会 —— 它在等云端的两台机器（macOS + Ubuntu）干活。

| 它在做 | 为什么要这么久 |
|---|---|
| 建仓库、推代码 | 十几秒。里面有个 8 MB 的中文字体，慢一点是正常的 |
| 在 GitHub 的 **macOS** 机器上装 Flutter | 几分钟。那台机器每次都是全新开机的 |
| 编译 iOS 版 App | 几分钟。Xcode 编译本来就慢 |
| 启动 **iOS 模拟器**、装 App、启动 | 一两分钟 |
| **录 45 秒功能屏** | 45 秒 —— App 自动走「首页 → 记一笔 → 保存 → 统计 → 切月份」 |
| 同时在 Ubuntu 上编 Android、启动模拟器、录屏 | 和 iOS 并行，不额外占你的时间；安卓要多编一个自动演示版 APK |
| 截图、打包、上传 | 十几秒 |
| 你把包下载下来 | 十几秒 |

**关键的一点：那台 Mac 是 GitHub 免费给你的，你不需要有 Mac。**
公开仓库用 GitHub 官方的构建机器，分钟数免费且不限量。

## 4. 关于「双端」和「原生」，要说得准确

招聘写的是「Android 或 iOS 原生技术」，还提到「双端原生 demo」。

**这个项目是 Flutter 一套代码编译到 Android 和 iOS 两端。**
它有两个真实的原生工程目录，但不是 Kotlin 和 Swift 各写一套：

| 招聘要的 | 在哪 | 怎么证明 |
|---|---|---|
| 安卓端能跑 | `dist\demo-android.mp4` | 脚本刚给你的安卓模拟器录屏 |
| iOS 端能跑 | `dist\demo-ios.mp4` | 脚本刚给你的 iOS 模拟器录屏 |
| 安卓工程 | `app/android/` | 真的 Gradle 工程，有 `build.gradle.kts`、`AndroidManifest.xml`、`MainActivity.kt` |
| iOS 工程 | `app/ios/` | 真的 Xcode 工程，有 `project.pbxproj`、`Info.plist`、`AppDelegate.swift` |

邮件里**建议写**：

> 用 Flutter 实现 Android + iOS 双端记账 App，后端 Node.js，附两端模拟器录屏。

**不建议写「双端原生」**。Flutter 不是原生开发框架，懂行的人一问就能问出来，
反而会把注意力从「东西真的能跑」转移到措辞上。诚实写法不影响录用，
夸大写法会。

> 如果招聘方硬性要求 Kotlin 或 Swift 原生项目，那这个项目不满足那一条，
> 需要另外用原生技术做一个 demo。这一点脚本帮不了你。

## 5. 出错了怎么办

**脚本的设计原则是：出错时打印原始报错，并且告诉你该怎么把它交给 AI。**
不会给你一句含糊的"操作失败"。

卡住时你会看到这样一段：

```
  卡在「交付流程」这一步了

不要慌，也不要自己猜。把下面这一整段原样复制给 AI（或贴给我）...

  ---------- 从这里开始复制 ----------
  步骤：交付流程
  报错：GitHub API GET /repos/<你的用户名>/moneynote 返回 401
  详情：
    Bad credentials
    ...
    401 = 令牌无效。多半是：复制少了字符、令牌过期了、或者已经被撤销。
  ---------- 复制到这里 ----------
```

**照着做就行**：把中间那段复制出来，发给我或者任意 AI。

> 脚本**不会**把令牌内容打进任何报错里 —— 万一 `git push` 的报错里带了令牌，
> 它会被换成 `***已隐藏***`。所以你可以放心复制。

### 常见情况速查

| 现象 | 多半是什么 | 怎么办 |
|---|---|---|
| `401 Bad credentials` | 令牌复制少了字符，或已过期 | 删掉 `secrets\token.txt`，重跑一次，会请你重新粘 |
| `403` | 令牌没勾 `repo`/`workflow` | 去 GitHub 重新生成一个，勾上这两个 |
| `git push` 报 `rejected` / `non-fast-forward` | 建仓库时勾了 "Add a README file" | 把那个仓库删掉重跑（最干净），或看脚本给的 B 方案 |
| 仓库建好了但 HR 打不开 | 仓库是私有的 | 脚本会自动把它改成 Public；改不动会报错并说明原因 |
| 探到一半卡在「检查环境」 | 网络 | 如果开着代理/加速器，试着关掉再跑一次 |
| 构建那一步红了 | 见下 | |

### 构建失败（那一大步红了）

这是**整条路里唯一一个没法在本地预先验证的环节**（这台机器没有 macOS，
谁也没法在 Windows 上先试一遍 iOS 编译）。所以它也是最可能出问题的一步。

**但失败信息是有用的**：打开脚本打印的那个运行页面链接，
往下滚找到**第一个打红叉**的步骤，把它的日志整段复制给 AI。

最可能的原因是 **Xcode 版本和 Flutter 3.47.7 对不上**。
如果是这一类，把 `.github/workflows/ios-build.yml` 里的 `macos-15`
改成 `macos-26`，再跑一次。文件里那一段长注释就是讲这个的。

## 8. 踩过的坑（都写进代码注释了）

这些是实际调试时撞上的，不是编的。你可以跳过，但面试时它们是很好的谈资。

### 坑 1：GitHub 的证书在这台机器上验不过

**现象**：脚本第一步就死，报 `fetch failed`。但同一时刻百度、npm、ipinfo 全都正常。

**查出来的原因**：本机的 HTTPS 流量被一层**本地根证书**重新签发了
（常见来源：杀毒软件的网页防护/HTTPS 扫描、公司代理、本机代理工具）。
两个佐证：一是 TCP 握手只要 **4.5 毫秒** —— 从国内连 GitHub 的新加坡节点不可能这么快；
二是 curl 也报证书错误。

而 **Node 不读 Windows 的证书库**，它用自己捆绑的一份 Mozilla CA 列表，
里面没有那个本地根证书。实测对照：

| | Node 自带 CA | `--use-system-ca` |
|---|---|---|
| `api.github.com` | ❌ 验不过 | ✅ HTTP 200 |
| 百度 / npm / ipinfo | ✅ | ✅ |

**注意这个坑阴在哪**：**只有 GitHub 中招**。所以"我别的网站都能上啊"这个判断完全靠不住。

**脚本的处理**：启动时先探一下，通不过就自动用 `--use-system-ca` 把自己重启一遍。
在**没有拦截的正常网络里完全不受影响**。

### 坑 2：`--use-system-ca` 会让 Node 在退出时崩

修完坑 1，脚本跑完了，但末尾吐出一段 C 源码断言：

```
Assertion failed: !(handle->flags & UV_HANDLE_CLOSING),
file src\win\async.c, line 76
```

退出码变成 **127** —— 而它**其实已经成功拿到了 HTTP 200**。实测三种写法：

| 写法 | 结果 |
|---|---|
| `fetch` 之后立刻 `process.exit(0)` | 打印了 HTTP 200，**退出码 127** ❌ |
| `await fetch` 之后自然结束 | 退出码 **0** ✅ |
| `await fetch` + 等 2 秒 | 退出码 **0** ✅ |

**结论**：带 `--use-system-ca` 时不能在 fetch 之后强退。
所以脚本里全部改成了设 `process.exitCode`、让进程自然结束。
**不改的话，你会在一切成功之后看到一段吓人的崩溃报错。**

### 坑 3：`.bat` 里不能出现任何中文（连注释都不行）

我在批处理里写了一行中文注释，结果：

```
'SCII' 不是内部或外部命令
'oy.mjs' 不是内部或外部命令        ← 本来是 node "scripts\deploy.mjs"
'数就不停（给自动化用）...' 不是内部或外部命令
```

**原因**：cmd.exe 是按当前代码页（中文 Windows 上是 GBK）**逐字节**解析 `.bat` 文件的，
而文件存的是 UTF-8。一个中文字符占 3 个字节，cmd 按 GBK 读就是 1.5 个字符，
"当前读到第几字节"会算错 —— **下一行会被从头吃掉一两个字符**。
那条中文注释自己也被当成命令执行了。

`chcp 65001` 修不了这个（那一行本身也要被解析）。

**所以 `一键交付.bat` 是纯 ASCII 的，一个中文字符都没有** —— 包括注释。
所有中文输出都从 `scripts/deploy.mjs` 打印，Node 写 stdout 用的是确定的 UTF-8。

### 坑 4：`tar` 不等于 `tar`

解压录屏（一个 zip）时，如果直接写 `tar -xf x.zip`，
在这台机器上命中的是 **Git 自带的 GNU tar**，它**不认识 zip**：

```
tar: This does not look like a tar archive
```

而 Windows 自带的 `C:\Windows\System32\tar.exe` 是 **bsdtar**，它认识 zip
（实测中文文件名也正常）。所以脚本里用的是**绝对路径**，不是 `tar`。
