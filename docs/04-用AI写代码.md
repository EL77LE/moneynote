# 04 · 用 AI 写代码的正确姿势

**这份文档是全套里最重要的。** 代码是死的，方法是活的。

招聘方想看"用 AI 协作做出来的原生 App"——真正在筛的不是"你会不会让 AI 写代码"（那谁都会），而是**"你能不能为一个 AI 参与的项目负责"**。

---

## 一、先接受一个残酷事实

`ltx@techlz.com` 这封招聘里的"vibe coding"，**不是**"AI 写我不管"。

面谈一定会发生这样一段对话：

> **面试官**：你这个记账 App 的统计页，分类占比的柱子长度，是按什么算的？
>
> **你**：呃……AI 写的，我调了调 UI。
>
> **面试官**：那你知道它为什么不用第三方图表库吗？
>
> **你**：……

十秒钟，这个项目从加分项变成"这人不可信"的证据。

**所以：你可以让 AI 写 95% 的代码，但你必须能解释 100% 的代码。**

---

## 二、三个必死的误区

### ❌ 误区一：让 AI 一次写完整个 App

```
帮我写一个记账 App，Flutter 做的，要好看
```

结果：AI 给你 800 行代码，扔进一个文件里。
问题不是它写得烂，是**你没法验收**。出错了你不知道错在哪，想改一个颜色得在 800 行里找。

### ❌ 误区二：不读代码

跑起来了，截图发出去，完事。
后果：第 1 周很爽，第 4 周面谈当场露馅，而且**连改都改不动**——因为你看不懂。

### ❌ 误区三：报错就整段贴给 AI

```
运行报错了
<贴 200 行日志>
帮我改好
```

AI 会开始猜。它会重写整个文件，引入新的 bug，你再贴一次，它再改……三轮之后代码已经跟你的理解完全脱节了。

---

## 三、正确的流程（本项目就是这么做的）

### 第 1 步：先定数据契约，再写代码

**在写任何界面之前，先确定 API 长什么样。** 因为这是前后端唯一必须达成一致的东西。

```
POST /api/records
请求: { "type": "expense", "amount": 25.5, "category": "餐饮",
        "note": "午饭", "date": "2026-10-15" }
成功: 201 + { "id": 1, "type": "expense", ... , "createdAt": "..." }
失败: 400 + { "error": { "code": "BAD_AMOUNT", "message": "..." } }
```

这三行定完，前后端就可以**并行开工**了。定之前开工，等着返工。

### 第 2 步：定分层，让 AI 知道"什么代码放哪"

```
lib/
├── core/      纯工具，不依赖任何东西
├── models/    数据结构 + JSON 互转
├── data/      网络、缓存（不碰界面）
├── state/     状态（不碰 HTTP）
├── widgets/   可复用组件
└── pages/     页面（只调 state）
```

规矩定死：**`pages/` 不许直接 `import '../data/api_client.dart'`。** 想发请求就调 `AppState`。

为什么重要：面试官问"要换成 WebSocket 实时同步你改哪"，你能立刻答"只改 `data/` 和 `state/`，页面一行不动"。这就是分层唯一的意义。

### 第 3 步：一次只让 AI 写一个文件

```
背景：Flutter 项目，状态用 ChangeNotifier + InheritedNotifier，没引状态管理库。
      数据层在 lib/data/，页面在 lib/pages/。

任务：写 lib/widgets/category_bar.dart，一个分类占比条。

约束：
- 必须是 StatelessWidget
- 不要引入新依赖
- 不要用 withOpacity（已废弃），用 withAlpha
- 条形宽度用 LayoutBuilder 拿，不要写死像素值
- 颜色由调用方传进来，组件自己不决定颜色

验收标准：
- flutter analyze 无 warning
- 占比 0% 时条长为 0，100% 时铺满
- 金额很小的分类（占比 0.5%）也要看得见
```

**四个要素缺一不可**：背景、任务、约束、验收标准。

"约束"尤其关键。没有它，AI 会顺手给你引一个 `fl_chart` 依赖，而你根本不知道多了一个包。

### 第 4 步：写完立刻跑，不要攒

```
flutter analyze
flutter test
flutter run
```

**每写完一个文件就跑一次。** 出错时你只知道"是刚才那个文件的问题"，范围 5 分钟就能定位。攒了 5 个文件再跑，出 3 个错，你就得从头猜。

### 第 5 步：报错时这样问

```
运行 flutter run 编译报错：

<粘贴完整错误，从报错行往上多贴 10 行>

我的理解：这个错误是说 LayoutBuilder 不能直接放在 Column 里，
因为 Column 在竖直方向给的是无界约束，LayoutBuilder 拿不到 maxWidth。

我已经确认：报错的文件是 lib/widgets/category_bar.dart 第 42 行，
它确实在一个 Column 的直接子节点位置。

预期：能编译通过。
实际：报下面这个错。

请只告诉我这一处该怎么改，不要重写整个文件。
```

**最后一句是精髓。** 它把 AI 从"重写模式"锁进"回答模式"，避免它顺手把你之前写对的地方也改坏。

## 四、一个真实例子：这个项目里抓到的 bug

写完 `lib/core/format.dart` 里的月份切换函数后，我写了单元测试：

```dart
expect(shiftMonthStr('2026-01', -1), '2025-12');
```

**没通过。** 返回的是 `2026-12`。

原因：原来的写法是

```dart
var mon = month + delta;      // 1 + (-1) = 0
year += (mon - 1) ~/ 12;      // (0-1) ~/ 12 = -1 ~/ 12
```

Dart 的 `~/` 是**向零截断**，不是向下取整。`-1 ~/ 12 == 0`，所以年份没往前退。

改成先换算成"从 0 年起的总月数"：

```dart
final totalMonths = year * 12 + (mon - 1) + delta;
final newYear = totalMonths ~/ 12;   // 此时一定非负，~/ 才等价于地板除
final newMon = totalMonths % 12 + 1;
```

**这个故事本身就是一个很好的面谈素材**：不是"我写对了"，而是"我用测试发现了一个边界 bug，定位到是语言整除语义的差异，改完加了测试锁住行为"。

面试官听到这种回答，对你的信任度完全不一样。

## 五、第 2 周的练习清单（别跳过）

按难度排序，做完前三个，你就真的会了。

### ⭐ 加一个「宠物」支出分类

改 `lib/core/categories.dart` 加一行 `CategorySpec('宠物', Icons.pets)`。
再去 `backend/src/seed.js` 的 `EXPENSE` 数组里加一条，`npm run seed` 重跑。

**练的是**：看懂两个仓库怎么协作。

### ⭐⭐ 首页显示「本月最大的一笔支出」

数据其实已经有了——`stats.byCategory[0]` 就是最大的分类，但"最大单笔"没有。
你需要：在 `backend/src/repo.js` 的 `getStats` 里加一个查询 → 在 `MonthStats` 模型里加字段 → 在 `SummaryCard` 里显示。

**练的是**：从后端到前端的完整数据链路。这是面谈最容易被追问的地方。

### ⭐⭐ 让统计页支持「按周」

后端加一个 `GET /api/stats?from=&to=` 的分支，前端加一个切换控件（复用 `SegmentedButton`）。

**练的是**：读懂现有的参数校验逻辑，扩展而不是重写。

### ⭐⭐⭐ 删除后支持「撤销」

现在删了就没了。改成：删除后底部弹一个「已删除 · 撤销」，5 秒内点撤销就恢复。

难点在设计：你是真删了再重建，还是标记删除？重建的话 id 会变，你接受吗？
**这道题的答案没有对错，但能讲清楚取舍就是一流的回答。**

### ⭐⭐⭐ 备注搜索

首页加一个搜索框，能按备注和分类名过滤。要考虑：搜索是前端过滤还是后端过滤？数据量大了怎么办？

## 六、面谈时怎么介绍这个项目

**别这么说**：
> 这是我用 AI 做的一个记账 App，功能有记账、统计、分类……

这是"我在描述一个东西"，人人都能说。

**要这么说**：

> 这是一个记账 App，一套 Dart 代码编译成 Android 和 iOS 两个原生包。
> 后端是我自己写的 Node + Express，数据库用的是 Node 内置的 SQLite。
>
> 有三个地方我想重点说一下：
>
> 第一，**金额我存的是整数「分」而不是小数**。因为 `0.1 + 0.2` 在浮点下不等于 `0.3`，累加多了账目会对不上。数据库存分，只在 API 出入口做一次换算。这个我写了测试锁住。
>
> 第二，**日期我用 `YYYY-MM-DD` 字符串存，不用 DateTime**。这样彻底避开了「本地时区 vs UTC 差一天」这类问题，字符串比较就等于日期比较。
>
> 第三，**我做了离线优先**。打开 App 先亮本地缓存，再去请求网络。后端挂了或者没信号，照样能看到上次的数据。网络失败也不清空界面，只在顶部挂个提示条。
>
> 还有一个我自己抓出来的 bug：月份切换函数我用 `~/` 做除法，但 Dart 的 `~/` 是向零截断不是向下取整，所以「1 月往前推一个月」算出来是同年 12 月。写单元测试的时候才暴露出来。
>
> 面试官：**那你现在明白了 Dart 的整除是怎么设计的吗？**

最后那句是面试官自然会接的话。你要能答上来。

## 七、AI 协作的红线

- ✅ **让 AI 写**：样板代码、重复的 UI、报错信息的解释、你不熟的标准库用法
- ✅ **让 AI 解释**：看不懂的代码、奇怪的报错、替代方案对比
- ❌ **别让 AI 决定**：架构分层、数据怎么存、要不要引依赖、API 契约怎么定
- ❌ **别交你没跑通的代码**：录屏前一定要完整走一遍

**一句话总结**：AI 是打字快十倍的程序员，但**你是那个要为结果负责的人**。
