# 15 · 双端原生：一键交付

> 目标：拿到 **项目链接** + **Android 原生录屏** + **iOS 原生录屏**，发到 `ltx@techlz.com`。
> 本机不需要 Android SDK、Xcode、Mac。编译和录屏都在 GitHub Actions 上完成。

---

## 0. 先做一次安全清理

如果 GitHub token 曾经出现在聊天、截图、录屏里：

1. 打开 GitHub → Settings → Developer settings → Personal access tokens
2. 找到旧 token，点 **Revoke**
3. 新建一个 **classic token**，只勾：
   - `repo`
   - `workflow`
4. 把新 token 保存到 `secrets/token.txt`，**不要发到聊天里**

`secrets/` 已在 `.gitignore` 里，不会被提交。

---

## 1. 一键出片

双击根目录的 `一键交付.bat`。

它会自动：

| 步骤 | 结果 |
|---|---|
| 建公开仓库、推代码 | `https://github.com/<你的用户名>/moneynote` |
| 触发 `native-ios-build.yml` | SwiftUI 在 macOS 模拟器里自动演示并录 45 秒 |
| 触发 `native-android-build.yml` | Kotlin/Compose 在 Android 模拟器里自动演示并录 45 秒 |
| 下载产物 | `dist\demo-ios.mp4`、`dist\demo-android.mp4`、APK、截图 |

演示流程是固定的：**首页 → 记一笔 → 保存 → 统计 → 切月份**。  
演示模式只在 CI 构建时开启：Android 用 `-PdemoMode=true`，iOS 用启动参数 `--demo`。正常安装包不会自动操作。

第一次跑如果红叉，打开 Actions 日志里第一个打红叉的步骤，整段复制给 AI；不要自己猜。

## 2. 部署云端后端（让手机不依赖这台电脑）

1. 打开 Render：  
   `https://render.com/deploy?repo=https://github.com/<你的用户名>/moneynote`
2. 用 GitHub 登录，点 **Apply** / **Deploy Blueprint**
3. 等状态变成 **Live**
4. 浏览器打开：  
   `https://<你的服务名>.onrender.com/api/health`  
   看到 `{"ok":true}` 就成功

`render.yaml` 已经写好：根目录 `backend`、启动命令、`AUTO_SEED=1`、健康检查。免费实例的 SQLite 是临时磁盘，重启会清空；`AUTO_SEED=1` 会在空库时自动补演示数据，不会影响演示。

### 让它一直在线（电脑关机也不休眠）

仓库里自带 `.github/workflows/keep-alive.yml`：GitHub 每 5 分钟访问一次 `/api/health`。Render 免费实例要 15 分钟无流量才休眠，5 分钟一次足够把它保持醒着，**不需要你的电脑开着**。

如果 Render 给你的域名不是 `moneynote-api.onrender.com`：

1. 打开 GitHub 仓库 → Settings → Secrets and variables → Actions
2. 切到 **Variables**，新建 `BACKEND_URL`
3. 值填 `https://你的服务.onrender.com`
4. 到 Actions →「后端保活」→ Run workflow 手动跑一次，确认绿色

**边界**：免费档 + 保活是「实际可用」，不是云厂商的 SLA 承诺。GitHub 的定时任务可能延迟，仓库连续 60 天无活动也可能被暂停定时任务。  
可以再加一个 **UptimeRobot** 免费监控（5 分钟一次，直接监控 `/api/health`）做双保险，它不依赖 GitHub。  
如果你要严格 always-on，把 `render.yaml` 里的 `plan: free` 改成 `plan: starter`，在 Render 绑定付款方式后重新部署；付费实例不会休眠。

## 3. 让 Android APK 连公网

拿到 Render 地址后，在本机 PowerShell / cmd 里执行：

```bat
set API_BASE_URL=https://<你的服务名>.onrender.com
一键交付.bat
```

这次 `native-android-build.yml` 会编译出连公网的正常版 APK。`一键交付.bat` 会把它下载成 `dist\moneynote-native.apk`；Actions 的 `native-android-apk` artifact 里也有一份。

装到 Android 手机上后，**这台电脑关机、手机用流量/别的 Wi-Fi，仍然能记一笔、看统计**。

iOS 真机安装需要 Apple 开发者签名；当前交付的 iOS 证据是 **Xcode 模拟器录屏**，不是真机安装包。这一点邮件里要如实写。

## 5. 常见问题

**Q：iOS 工作流在 `xcodegen generate` 失败？**  
看 `native/ios/project.yml` 是否被改坏；本地不需要装 XcodeGen，CI 会 `brew install xcodegen`。

**Q：Android 工作流在 Gradle 下载依赖时失败？**  
多半是网络抖动，重新跑一次；连续失败再看 `native/android/app/build.gradle.kts` 的版本号。

**Q：录屏里 App 显示「连不上后端」？**  
CI 里后端没起来。看 workflow 的「启动本机后端」步骤和最后的「后端日志」。

**Q：iOS 能装到真 iPhone 吗？**  
代码是原生 SwiftUI，可以用 Xcode 打开 `native/ios` 生成工程后签名安装；但需要 Apple 账号/证书，不属于零基础一键流程。

**Q：Flutter 版还要吗？**  
`app/` 保留作跨平台备份。投递主项目是 `native/android` + `native/ios`，邮件里不要写 Flutter。
