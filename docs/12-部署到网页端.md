# 12 · 部署到网页端

**这一步能得到什么：一个网址。HR 点开就能用，不用装 APK、不用安卓手机。**

投递里最尴尬的情况是：你写了「双端原生 Demo」，对方回一句
「我这边是 iPhone，有安装包吗」。

一个能直接点开的网址把这个问题彻底解决掉——
**而且它是唯一能让 HR「零成本」看到你东西的方式。**

> ⚠️ 先说清楚定位：**网页版是加分项，不是替代品。**
> 招聘要的是 Android / iOS 原生。网页版的作用是"让对方 3 秒钟看到成品"，
> 真正要展示的原生能力还是靠 APK 和录屏（见 [05](05-录屏与打包.md)）。
> 顺序上：**先把 [11 上传 GitHub](11-上传到GitHub.md) 做完，再做这个。**

---

## 1. 前提：后端必须先上公网 HTTPS

网页版和 App 不一样：App 能连你的局域网后端，**网页不能**。

原因是一条浏览器安全策略，叫**「混合内容」（Mixed Content）**：

> **https 页面里发出的 http 请求，浏览器会直接掐断，连服务器都碰不到。**

而 GitHub Pages / Netlify / Vercel 给你的都是 https 域名。所以：

| 网页版地址 | 后端地址 | 结果 |
|---|---|---|
| `http://localhost:xxxx` | `http://localhost:3000` | ✅ 本地开发，可以 |
| `https://xxx.netlify.app` | `https://xxx.onrender.com` | ✅ 线上，正确 |
| `https://xxx.netlify.app` | `http://1.2.3.4:3000` | ❌ **一定失败** |

**所以先把 [06 部署后端到公网](06-部署后端到公网.md) 做完**，
拿到那个 `https://xxx.onrender.com` 地址。

> 代码里已经针对这个坑做了处理：万一真配错了，App 不会给你一句
> 莫名其妙的「Failed to fetch」，而是明确告诉你
> 「这个页面是 https 的，而接口地址是 http://…，浏览器会拦截」。
> 见 `app/lib/core/app_config.dart` 里的 `misconfigurationHint`。

## 2. web 平台目录：已经生成好了

Flutter 工程里 `android/`、`ios/`、`web/` 这些平台目录是 `flutter create`
生成的，不是手写的。**三个目录现在都已经在了**，你不用做这一步：

```bash
ls app/
# android  assets  ios  lib  test  web  pubspec.yaml  ...
```

> **万一你哪天需要重新生成某个平台目录**（比如手滑删了），正确姿势是
> 带上 `--platforms` 直接在 `app/` 里跑：
>
> ```bash
> cd app
> flutter create --org com.example --project-name money_note --platforms web .
> ```
>
> 很多老教程会让你"先建个临时目录生成再搬过来"，理由是怕覆盖
> `lib/main.dart`。**这个担心在带 `--platforms` 时不成立**——
> 实测过（对 `lib/main.dart` 和 `pubspec.yaml` 做了 md5 比对、
> 以及 `diff -rq` 全目录比对）：指定了 `--platforms` 之后，
> `flutter create` 只补平台目录，你已有的 Dart 代码一个字节都不动。
>
> 不带 `--platforms` 的老写法确实会重新生成 `lib/main.dart`——
> 所以**别用不带参数的老写法**就行。

做完 `app/` 下面应该多了一个 `web/`：

```
app/
├── android/
├── ios/
├── web/            ← 新加的
│   ├── index.html      ← 网页外壳
│   ├── manifest.json   ← 加到手机桌面时的名字和图标
│   ├── favicon.png
│   └── icons/
├── lib/
└── pubspec.yaml
```

### 2.1 改两个地方

**① `app/web/index.html`** —— 改标题和描述（浏览器标签页上显示的那个）：

```html
<title>MoneyNote 记账</title>
<meta name="description" content="双端原生记账 App 的在线演示版">
```

**② `app/web/manifest.json`** —— 改名字：

```json
{
  "name": "MoneyNote 记账",
  "short_name": "MoneyNote",
  ...
}
```

改完保存，这一步就完成了。

## 3. 本地先跑一遍（**别跳过**）

线上部署出问题很难查，先在本地确认网页版是好的。

```bash
cd app
flutter run -d chrome
```

第一次会编译一会儿，然后自动弹出 Chrome。

**要确认三件事：**

1. 界面出来了，顶部卡片显示「2026年10月结余 ¥X,XXX.XX」
2. 列表里有数据
3. 按 `F12` 打开开发者工具 → **Console** 标签页，**没有红色的报错**

> **本地这时的后端可以是本机的 `http://localhost:3000`**，
> 因为页面本身也是 `http://localhost`，两边都是 http，不算混合内容。
> 这是唯一能用 http 后端的场景。

关掉的时候在终端按 `q`。

### 3.1 本地就出问题的话

| 现象 | 多半是什么 |
|---|---|
| 白屏，Console 里一堆 404 | `web/` 目录没搬对，回第 2 步 |
| 中文显示成 □□□ 方块 | 见第 7 节，这是中国网络的经典坑 |
| 提示「连不上 http://localhost:3000」 | 后端没开 |
| 别的 | 把 Console 里**红色那几行**整段复制给 AI |

## 4. 构建成静态文件

Flutter 网页版本的产物是**一堆静态文件**（HTML + JS + WASM），
丢到任何静态托管上就能跑。

```bash
cd app

flutter build web --release --dart-define=API_BASE_URL=https://你的后端地址
```

> 把 `https://你的后端地址` 换成 [06](06-部署后端到公网.md) 拿到的那个。

产物在 `app/build/web/`。里面应该有：

```
build/web/
├── index.html
├── main.dart.js
├── flutter_bootstrap.js
├── assets/
└── canvaskit/          ← 渲染引擎，体积大头
```

### 4.1 关于 `--base-href`（**只有一个情况需要**）

| 部署到哪 | 要不要加 |
|---|---|
| **Netlify** / Vercel / 自己服务器（域名根目录） | **不用加** |
| **GitHub Pages**（地址是 `用户名.github.io/仓库名/`，不是根目录） | **必须加**：`--base-href /你的仓库名/` |

**加错的后果很迷惑**：页面能打开，但是**永远白屏**，
Console 里报 `main.dart.js 404`。你会以为是部署失败，
其实文件在 `/仓库名/main.dart.js`，而 index.html 去 `/main.dart.js` 找了。

GitHub Pages 的完整命令长这样：

```bash
flutter build web --release \
  --base-href /moneynote/ \
  --dart-define=API_BASE_URL=https://你的后端地址
```

（`moneynote` 换成你实际的仓库名。）

## 5. 路线 A：Netlify Drop —— 最快，推荐先用这个

**不用装任何工具，不用命令行，拖一个文件夹上去就行。** 大概 3 分钟。

1. 用第 4 节的命令构建（**不要加 `--base-href`**）
2. 浏览器打开 <https://app.netlify.com/drop>
3. 把 **`app/build/web` 这个文件夹**直接拖进页面中间那个虚线框
   - ⚠️ 拖**文件夹本身**，不是拖里面的文件
4. 等十几秒，页面上会给你一个网址，类似
   `https://sparkly-cat-123abc.netlify.app`
5. 点开那个网址验证

这时候它是匿名站点，**要登录才会永久保留**。
建议点 `Claim your site` 用 GitHub 账号登录一下（免费），
然后可以在 `Site configuration` → `Change site name` 改成好记的，
比如 `moneynote-zhangsan`。

**这个网址就可以直接填进邮件了。**

> **加不了新的记录？** 先检查后端地址对不对，再检查 CORS —— 见第 8 节。

## 6. 路线 B：GitHub Pages —— 自动化，能加分

路线 A 的问题是：**每次改代码都要重新拖一遍**。

路线 B 把这件事交给 GitHub Actions，**你只要 `git push`，
它自动构建、自动部署**。多花的这点时间换来的是面试时一句
「我配了 CI，推上去自动发布」——**这是实打实的工程习惯**。

工作流文件我已经写好了：`.github/workflows/web-deploy.yml`。

### 6.1 要配一个变量

1. 打开仓库 → **Settings** → 左边栏 **Secrets and variables** → **Actions**
2. 切到 **Variables** 标签（**不是** Secrets）
3. **New repository variable**
   - Name：`API_BASE_URL`
   - Value：`https://你的后端地址`
4. 保存

> **为什么是 Variable 不是 Secret？**
> 后端地址不是密码，写在这儿更透明，构建日志里也能直接看见。
> 真正的密钥才放 Secret。

### 6.2 打开 Pages

1. 仓库 → **Settings** → 左边栏 **Pages**
2. **Source** 选 **GitHub Actions**（不是 "Deploy from a branch"）
3. 保存

### 6.3 跑一次

1. 仓库 → **Actions** 标签 → 左边选「部署 Web 版到 GitHub Pages」
2. 右边 **Run workflow** → 绿色的 **Run workflow** 按钮
3. 等 1～3 分钟（第一次要装 Flutter，慢一些）
4. 变成绿色对勾之后，回到 **Settings → Pages**，
   顶部会显示 `Your site is live at https://用户名.github.io/仓库名/`

### 6.4 以后怎么更新

```bash
git add .
git commit -m "feat: 加了新分类"
git push
```

就这样。剩下的 GitHub 自己会做。

## 7. ⚠️ 中国网络特别注意

**这一节很重要。** 招聘方大概率在国内，这两件事会决定他能不能打开你的链接。

Flutter 网页版默认会去 **Google 的 CDN（`gstatic.com`）** 下载两样东西：

| 下载什么 | 不下载会怎样 |
|---|---|
| **CanvasKit 渲染引擎**（约 5 MB） | **整个页面白屏**，什么都看不到 |
| **Noto 中文字体** | 中文**全部显示成 □□□ 方块** |

而 `gstatic.com` 在国内**是打不开的**。

**这两件事本项目都已经处理好了**，你不用再动手。下面写的是为什么，
以及怎么自己验证一遍——因为面试官很可能问到。

### 7.1 渲染引擎：已经解决

**每次构建都加上 `--no-web-resources-cdn`**，引擎就打包进产物了：

```bash
flutter build web --release \
  --no-web-resources-cdn \
  --dart-define=API_BASE_URL=https://你的后端地址
```

（本项目的 GitHub Actions 工作流里已经带上了这个参数。）

**怎么确认它真的生效了**（我在这台机器上验过）：

```bash
ls app/build/web/canvaskit/
# canvaskit.js  canvaskit.wasm  skwasm.js  skwasm.wasm  ...
```

目录在、文件有，就说明引擎在本地了。产物里能搜到
`gstatic.com/flutter-canvaskit` 这个字符串，但那只是**用不到的兜底默认值**——
同目录的 `flutter_bootstrap.js` 里写着 `"useLocalCanvasKit":true`，
引擎读到这里就走本地，不会去碰网络。

### 7.2 中文字体：这个才是真坑，**已经修好了**

先说结论：**这份代码已经带了中文字体，中文不会变方块。**
下面是它为什么必须带 —— 以及一个连 AI 都会答错的细节。

#### 实测到的现象

我把 `fonts.gstatic.com` 屏蔽掉，再打开网页版，看到的是这样：

- 界面、排版、图标、数字 **全部正常**（¥4,568.32 显示得好好的）
- **每一个汉字都是 □ 方块**

对照组（不屏蔽 gstatic）打开，中文一个不缺地全部正常。

**所以你不用去猜"国内会不会有问题"，答案是会，而且只坏中文。**

#### 为什么会这样

手机的渲染是靠操作系统的字体系统，中文字体系统里本来就有。
**Web 不是这样**：Flutter 网页版的 CanvasKit 引擎是**自己画字**的，
它看不见、也用不了浏览器的系统字体。遇到手里没有的字形，
它会去 `fonts.gstatic.com` 下载对应的 Noto 字体。

而 `--no-web-resources-cdn` **只管引擎，不管字体** ——
字体还是走那个域名。这是 Flutter 自身遗留的问题
（[issue #163823](https://github.com/flutter/flutter/issues/163823)、
[#163554](https://github.com/flutter/flutter/issues/163554) 都还开着），
在 3.47.7 上依然如此。

> 顺带说一句：老的 `--web-renderer html` 渲染器是用浏览器排版的，
> 能直接用系统字体，所以没这个问题。但**它在 Flutter 3.29 被删掉了**，
> 网上那些"加个 `--web-renderer html` 就好了"的答案都已经过期。

#### 修法：把字体打进产物，就不用联网下载了

**本项目已经做完了**，三个文件：

**① `app/assets/fonts/NotoSansSC-Regular.otf`** —— 字体本身，8.3 MB。
用 Noto Sans SC，OFL 开源协议，可自由分发。

**② `app/pubspec.yaml`** 里声明它：

```yaml
flutter:
  uses-material-design: true

  fonts:
    - family: NotoSansSC
      fonts:
        - asset: assets/fonts/NotoSansSC-Regular.otf
```

**③ `app/lib/theme.dart`** 里设为 Web 默认字体：

```dart
import 'package:flutter/foundation.dart' show kIsWeb;   // ← 这一行不能少
import 'package:flutter/material.dart';

const String webFontFamily = 'NotoSansSC';

ThemeData buildTheme(Brightness brightness) {
  ...
  return ThemeData(
    colorScheme: scheme,
    fontFamily: kIsWeb ? webFontFamily : null,
  );
}
```

> ### ⚠️ 这里有个连 AI 都会答错的坑
>
> 网上（以及不少 AI 的回答里）写着："`kIsWeb` 不用额外 import，
> `material.dart` 已经连带导出了。"
>
> **这是错的。** 我照着写，`flutter analyze` 直接报：
>
> ```
> error - Undefined name 'kIsWeb' - lib\theme.dart:59:17
> ```
>
> 必须老老实实写 `import 'package:flutter/foundation.dart' show kIsWeb;`。
> `show kIsWeb` 是为了只引这一个符号，不引入整个 foundation。

> **为什么只在 Web 上用，不干脆全平台都用？**
> 因为只带了 Regular 一个字重。手机上用系统字体，粗体是**真粗体**；
> 换成这个，粗体得靠引擎"描边加粗"凑出来，反而更糊。
> 手机系统本来就是中文的，没必要换。
>
> **代价**：8.3 MB 会进到所有平台的产物里（pubspec 的 assets 没有"分平台"这回事）。
> 也就是说 APK 也会大 8 MB 左右。对演示项目来说值——**中文变方块是致命的，
> 大 8 MB 不是**。

### 7.3 首次打开要等几秒，别让 HR 看到白屏

上面那些资源加起来约 7 MB。**第一次**打开（浏览器还没缓存）在 4G 上要等几秒，
而这个时间 Flutter 默认给你的是**一片纯白** —— 招聘方点开链接看到白色，
第一反应是"这链接是坏的"，然后关掉。

所以 `app/web/index.html` 里放了一个载入动画：

![载入中](images/app-loading.png)

深色底 + 绿字 + 转圈，和 App 的主题一致。

**它不能只是"好看"，关键在什么时候消失**：它挂的是 Flutter 派发的
`flutter-first-frame` 事件，也就是**界面真的画出来了才摘掉**。
不是固定等 3 秒 —— 那样网络慢的时候会出现"动画没了但还是白屏"，
网络快的时候又白等。

```html
<script>
  window.addEventListener('flutter-first-frame', function () {
    document.getElementById('loading')?.remove();
  });
</script>
```

> 这个动画里的中文是**浏览器系统字体**画的，不经过 CanvasKit。
> 所以哪怕 7.2 的字体真出了问题，这一行"正在载入…"也还是好的。

### 7.4 怎么自己验一遍

**方法一（最省事）**：部署完，用**手机流量**（关掉 WiFi）打开你的网址。
中文正常就说明没问题。

**方法二（本机就能做，我用的就是这个）**：
用 headless 浏览器打开网页版，同时把 gstatic 解析成"不存在"：

```bash
node scripts/shoot.mjs docs/images
```

`scripts/shoot.mjs` 里带了这条参数：

```
--host-resolver-rules=MAP fonts.gstatic.com ~NOTFOUND, MAP www.gstatic.com ~NOTFOUND
```

然后**用眼睛看图**：中文清楚 = 字体生效；汉字是方块 = 没生效。
这一步不需要真的在国内，也不需要手机流量。

> 把 `MAP www.gstatic.com ~NOTFOUND` 一起去掉再拍一张，就是你做对照组的办法。
> 两张图放一起，正好是"网页版到底依赖不依赖 Google"这个问题最直接的回答。

## 8. 上线之后必须检查的三件事

### ① 用手机流量打开

用**手机 4G/5G**（关掉 WiFi）打开你的网址。这是最接近 HR 的真实环境。

- 能打开 + 中文正常 → ✅
- 白屏 → 见第 7 节
- 中文方块 → 见第 7 节

### ② 在浏览器里真记一笔

点「记一笔」→ 填金额 → 选分类 → 保存。

**保存不了就是 CORS 问题**：

后端（`backend/src/server.js`）默认允许所有来源，所以**正常情况下不用管**。
但如果你在 Render 上设了 `CORS_ORIGIN` 环境变量，就必须把网页版的地址加进去：

```
CORS_ORIGIN=https://moneynote-zhangsan.netlify.app,http://localhost:3000
```

多个地址用**英文逗号**隔开，**不要有空格**，**不要带结尾的斜杠**。

### ③ 刷新页面，数据还在吗

网页版的数据存在浏览器本地（`localStorage`）+ 后端数据库里。

- 刷新后数据还在 → ✅
- 数据没了 → 后端没接上，回第 ② 步

> ⚠️ 如果后端部署在 Render 的**免费档**，它 15 分钟没人访问就休眠，
> 而且**重新启动会清空数据库**（免费档的硬盘是临时的）。
> 所以**录屏、截图一定要趁后端活着的时候做完**，别等最后一天。
> 详见 [06](06-部署后端到公网.md)。

## 9. 常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 白屏 + `main.dart.js 404` | `--base-href` 加错了 | 见 4.1。GitHub Pages 必须加，Netlify 不能加 |
| 白屏 + Console 里 `gstatic.com` 超时 | 引擎没打进本地 | 见第 7 节，加 `--no-web-resources-cdn` |
| 一直停在「正在载入…」 | 资源没下完，或被 `--base-href` 卡住 | 打开 F12 的 Network 面板，看哪个文件红了 |
| 中文全是方块 | **中文字体没进产物** | 本项目的字体是打包进去的，出现方块说明 `app/assets/fonts/NotoSansSC-Regular.otf` 丢了、或 `pubspec.yaml` 的 `fonts:` 段被删了。见 7.2 |
| 页面出来了但没数据 | 后端地址错 / 后端没起 / CORS | 见第 8 节 |
| 提示「这个页面是 https 的…」 | **就是你配错了**，后端地址写成了 http | 换成 https 的地址重新构建 |
| 「Failed to fetch」 | 同上，或后端地址打不开 | 浏览器直接访问后端地址试试 |
| 拖拽上传报错 | 拖的是文件夹里的文件 | 拖**整个 `build/web` 文件夹** |
