# 05 · 录屏与打包

目标：拿到一段**能证明这是 Android + iOS 双端 App** 的录屏，和一份能装到别人手机上的安装包。

**预计耗时：半天。**

---

## 一、先说实话：iOS 这一端怎么办

你是 Windows 机器。**iOS 编译必须有 macOS**，这是苹果的工具链限制（Xcode 只跑在 macOS 上），不是 Flutter 的问题，也不是能绕过的。

三条路，按推荐度排：

| 方案 | 成本 | 能录到什么 | 适合 |
|---|---|---|---|
| **A. 借一台 Mac** | 0 元 | 完整交互录屏 | 有朋友/同事用 Mac |
| **B. 租云 Mac**（MacinCloud 等） | 约 ¥25/小时 或 ¥180/月 | 完整交互录屏 | 想一次做干净 |
| **C. GitHub Actions 的 macOS 机器** | 0 元（公开仓库免费） | 自动构建 + 模拟器启动录屏 | 完全没 Mac |

**我的建议**：先用 **C** 把「iOS 真的能编译能跑」这件事证明出来，同时用 **Android 录完整的交互视频**。真到了面谈、对方要求看完整 iOS 演示，再去租一小时云 Mac。

> 注意：招聘方看的是「你有没有把双端都跑通」。
> 一段 iOS 模拟器启动、首页数据渲染出来的录屏 + 一份成功的 iOS 构建日志，
> 比一个"我说我做了 iOS"要有力得多。

## 二、Android 录屏（本机就能做，效果最好）

> **不想装 Android SDK、也不想插数据线？**
> 仓库里的 `.github/workflows/android-build.yml` 会在 GitHub 的 Ubuntu 机器上
> 完成「编译 → 启动模拟器 → 录屏 → 上传」，全程云端，本机什么都不用装。
> 在仓库页 Actions 里选「安卓构建与录屏」→ Run workflow 即可。
> 代价是只能录到模拟器里的自动操作，不如真机 + scrcpy 灵活。
> 只想快速交作业的话，直接用 [14 一键交付](14-一键交付.md)，它会自动跑这个工作流。

### 2.1 装 scrcpy

别用手机自带的录屏，也别用 `adb shell screenrecord`（最长 3 分钟、码率低、还依赖手机性能）。用 **scrcpy**：

下载：<https://github.com/Genymobile/scrcpy/releases> → 找 `scrcpy-win64-vX.X.zip` → 解压到 `C:\scrcpy`

它本来是"把手机屏幕投到电脑上并可以用鼠标操作"的工具，顺带能录像，画质好、时长不限。

### 2.2 用真机（推荐）

真机比模拟器流畅太多，录出来不卡顿。

```bash
# 手机连上电脑后
cd C:\scrcpy
scrcpy --record=D:\demo-android.mp4 --no-audio --max-size=1080
```

参数说明：
- `--record=` 录像文件路径
- `--no-audio` 不录音频（录屏不需要声音，还能减小体积）
- `--max-size=1080` 限制长边 1080，文件小很多，HR 也下得动

然后用**鼠标在电脑上的 scrcpy 窗口里操作手机**——比在手机上戳方便十倍，录出来也不会有手指遮挡。

### 2.3 用模拟器

```bash
scrcpy --record=D:\demo-android.mp4 --no-audio --max-size=1080
```

模拟器窗口必须先开着（`flutter run` 就会启动它）。

### 2.4 备选：adb 原生录屏

```bash
adb shell screenrecord --size 1080x2340 --bit-rate 8M --time-limit 180 /sdcard/demo.mp4
# 操作完毕后 Ctrl+C 结束
adb pull /sdcard/demo.mp4 D:\demo-android.mp4
```

限制：**最长 180 秒**，且受手机性能影响可能掉帧。只有 scrcpy 用不了时才用它。

## 三、iOS：GitHub Actions 方案

仓库里已经放好了一个工作流：`.github/workflows/ios-build.yml`。

它做这几件事：

1. 在 GitHub 的 macOS 机器上装 Flutter
2. **在同一个机器上把后端也启动起来**（iOS 模拟器跟宿主共享网络栈，所以 `localhost:3000` 直接能通）
3. 生成演示数据
4. 编译 iOS 模拟器版 App，装到模拟器上，启动
5. 用 `xcrun simctl io booted recordVideo` 录屏
6. 把录屏作为构建产物上传

### 怎么用

```bash
cd C:\Users\chenj\eclipse-workspace\demo0

git init
git add .
git commit -m "MoneyNote: Flutter 双端 App + Node 后端"

# 在 GitHub 上建一个仓库（建议 public，Actions 分钟数免费）
git remote add origin https://github.com/你的用户名/moneynote.git
git branch -M main
git push -u origin main
```

推上去之后：GitHub 仓库页 → **Actions** 标签 → 左边选「iOS 模拟器构建与录屏」→ **Run workflow**。

等 15～25 分钟，跑完之后在这次的运行页面底部 **Artifacts** 里下载 `ios-simulator-recording`。

### 这个方案能给到什么、给不到什么

✅ **能给到**
- 证明 iOS 端真的能编译、能装、能在 iOS 上跑起来
- 一段真实的 iOS 模拟器录屏（首页数据从后端加载出来的过程）
- 完整的构建日志 —— 这个其实很有说服力，截图放进邮件里

❌ **给不到**
- 自动点击/滑动的交互演示。GitHub Actions 上没法方便地模拟手指操作，所以录出来是"App 启动 + 首页渲染"，不是完整流程。

所以完整的交互演示，还是得靠 Android 那一份；或者借/租一台 Mac 补录。

### 想让 CI 录得更久一点？

`ios-build.yml` 里有个 `sleep 25`（在「启动 App」那一步），改成 `sleep 45` 就能多录一会儿。

## 四、90 秒录屏分镜（照着念就行）

录屏最忌"随手划拉两下"。按脚本走，90 秒能展示的信息量顶十分钟乱录。

先做准备：
1. 后端跑着，`npm run seed` 过了（有几十条数据，界面才好看）
2. 手机/模拟器时间调到白天，深色模式关掉（浅色在视频里更清楚）
3. 手机通知全部关掉，别录到微信弹窗
4. 电脑上的 scrcpy 窗口调到你想要的分辨率

| 时间 | 画面 | 你要做的事 |
|---|---|---|
| **0:00–0:08** | 首页 | 让画面静止两秒再开始。展示顶部卡片：本月结余、收入、支出、笔数 |
| **0:08–0:18** | 首页 | 慢慢往下滑，让按日期分组的流水滚过去。停留一下，让"今天/昨天/10月13日 周一"这些分组标题看清楚 |
| **0:18–0:25** | 首页 | 点顶部的「支出」筛选，列表只剩红色金额；再点「收入」，只剩绿色；点回「全部」 |
| **0:25–0:30** | 首页 | 点左箭头切成 9 月，数据变了；再点右箭头切回来，点「回到本月」 |
| **0:30–0:50** | 记一笔 | 点右下角 FAB。**慢慢来**：选「支出」→ 输入 `38.5` → 点「餐饮」→ 打开日期选择器（这里能展示中文日期选择器）→ 关掉 → 备注填「和朋友吃饭」→ 点保存 |
| **0:50–0:58** | 首页 | 新记录出现在列表顶部，顶部卡片的支出数字变了。**这里停顿两秒**，让观众看清数据是联动的 |
| **0:58–1:08** | 首页 | 点刚那条记录 → 进编辑页 → 改金额成 `88` → 保存 → 列表金额变了。再点进去 → 右上角删除 → 确认 → 回到首页，记录没了 |
| **1:08–1:20** | 统计 | 切到底部「统计」。展示收入/支出/结余三行，然后往下滚，展示分类占比条（有动画感地逐条露出）和每日趋势柱 |
| **1:20–1:30** | 收尾 | 回到明细页。**然后做一件很有说服力的事**：在电脑终端里把后端 `Ctrl+C` 停掉 → 回到 App 下拉刷新 → 顶部出现橙色「正在显示本地缓存」提示条，但**数据还在**。再启动后端 → 下拉刷新 → 提示条消失 |

**最后那 10 秒是整段视频的高光。** 它证明了你做了离线优先，而不是"界面写死了一堆假数据"。这是最能拉开差距的地方。

### 时长

**控制在 90 秒到 2 分钟。** 招聘方不会看完 5 分钟的视频。宁可少展示一个功能，也别让人中途关掉。

## 五、打包 APK（给别人装的安装包）

```bash
cd app
flutter build apk --release --split-per-abi
```

产物在 `app\build\app\outputs\flutter-apk\`：

- `app-arm64-v8a-release.apk` ← **发这个**（近几年所有安卓手机都是 arm64）
- `app-armeabi-v7a-release.apk` ← 老机器
- `app-x86_64-release.apk` ← 模拟器用

`--split-per-abi` 会让每个包只含一种架构，体积从 20MB 降到 8MB 左右。不加的话是一个包包含全部架构，40MB+。

### 打包前必做

1. **确认 AndroidManifest 里那两行还在**（INTERNET 权限 + cleartext，见 [03 第 4.1 步](03-跑通App.md)）。**已经替你配好了，这里是复查**——因为它一旦丢了，release 包里的 App 直接没网络，而调试版照样跑得好好的，你根本发现不了。
2. **打包后一定要真机装一次试试**：

```bash
adb install -r app\build\app\outputs\flutter-apk\app-arm64-v8a-release.apk
```

打开看看能不能拉到数据。**调试版能跑不代表 release 能跑**——这是这个项目最容易翻车的地方。

> 想让别人手机上装得上，对方需要在「设置」里允许「安装未知来源应用」。
> 或者你把 APK 传到百度网盘/阿里云盘，邮件里给链接。

### iOS 安装包

`flutter build ipa` —— **必须有 macOS**。GitHub Actions 那个工作流只出模拟器版（不需要签名），出真机包需要苹果开发者账号（$99/年）+ 证书配置。

对这次投递来说：**APK + iOS 模拟器录屏 + iOS 构建日志，足够了。** 别去折腾 99 美元。

## 六、视频文件怎么给

| 方式 | 优点 | 缺点 |
|---|---|---|
| **邮件直接附件** | 最方便 | Gmail 限 25MB，国内邮箱一般 50MB，超了发不出去 |
| **百度网盘 / 阿里云盘** | 不限大小 | HR 可能懒得点链接 |
| **B站 / YouTube 不公开链接** | 点开就能看，体验最好 | 需要账号 |

**推荐组合**：视频压到 20MB 以内直接附件 + 同时给一个网盘链接兜底。

压缩（用格式工厂，或者 ffmpeg）：

```bash
ffmpeg -i demo-android.mp4 -vcodec libx264 -crf 28 -preset slow -vf "scale=720:-2" demo-small.mp4
```

把 1080p 压到 720p、CRF 28，90 秒的视频大概 8～15MB，画质在手机上看完全够。
