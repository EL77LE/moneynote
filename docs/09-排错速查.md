# 09 · 排错速查

卡住了先来这里搜。**按报错关键字 Ctrl+F。**

---

## 一、万能三步

遇到任何问题的通用顺序，**别跳步**：

**第 1 步 · 读完整的错误信息**

从「第一行报错」往上多看 15 行。真正的线索几乎总是在上面。

**第 2 步 · 判断错误在哪一层**

| 现象 | 问题在哪 |
|---|---|
| `flutter analyze` / `flutter test` 报错 | 代码本身 |
| 编译通过但界面白屏/不刷新 | 状态管理或 widget 树 |
| 界面正常但没数据 | 网络层，或者后端没开 |
| 后端 curl 不通 | 后端或端口 |
| 只有 release 版有问题 | 打包配置（权限、混淆） |

**第 3 步 · 缩小到最小复现**

把最近改的东西**全部撤回**，确认它好了，再一点点加回来。加到哪一步坏，就是那里。

> 90% 的人在这一步偷懒，然后花三小时猜。
> **五分钟的二分法，胜过三小时的瞎猜。**

## 二、环境相关

| 报错 | 原因 | 解决 |
|---|---|---|
| `flutter : 无法将"flutter"项识别为 cmdlet...` | PATH 没生效 | 关掉**所有**终端重开。检查 `C:\src\flutter\bin\flutter.bat` 是否存在 |
| `cmdline-tools component is missing` | Android SDK 的 Command-line Tools 没装 | Android Studio → SDK Manager → SDK Tools → 勾上它 |
| `Android license status unknown` | 没接受许可 | `flutter doctor --android-licenses`，一路 `y` |
| `Unsupported class file major version 68` | Java 24 跟 Gradle 冲突 | `flutter config --jdk-dir="C:\Program Files\Android\Android Studio\jbr"`，然后 `flutter doctor -v` 确认 Java binary 指向变了 |
| `Unable to find bundled Java version` | Flutter 找不到 AS 的 JDK | 同上。有些版本的目录叫 `jre` 不是 `jbr` |
| 下载卡住 / `Connection timed out` | 镜像问题 | 检查 `FLUTTER_STORAGE_BASE_URL` 和 `PUB_HOSTED_URL`；或者删掉它们直连试试 |
| `Waiting for another flutter command to release the startup lock` | 上一个 flutter 进程没退干净 | 任务管理器杀掉所有 `dart.exe`；或删掉 `flutter\bin\cache\lockfile` |
| 模拟器起不来 / 卡成幻灯片 | 虚拟化没开 | `optionalfeatures` 里确认 Hyper-V 和虚拟机平台已勾。**或者直接用真机** |

## 三、后端相关

| 报错 | 原因 | 解决 |
|---|---|---|
| `EADDRINUSE: address already in use :::3000` | 端口被占 | `PORT=3001 npm run dev`；或 `netstat -ano \| findstr :3000` 找到 PID 再 `taskkill /PID xxx /F` |
| `Cannot find module 'express'` | 依赖没装 | `cd backend && npm install` |
| `node:sqlite` 相关报错 | Node 版本太低 | `node -v` 必须 ≥ 22.13。低于这个版本 `node:sqlite` 要加 `--experimental-sqlite` |
| `no such column: "xxx" - should this be a string literal in single-quotes?` | SQL 里用双引号写字符串了 | SQLite 的双引号是**标识符**不是字符串。改用单引号 |
| `SQLITE_BUSY` | 多个进程同时写 | 关掉多余的 `npm run dev` 进程 |
| 数据不对 / 想重置 | — | 删掉 `backend/data/` 整个文件夹，重新 `npm run seed` |
| `npm run smoke` 失败 | — | 看它打印的具体是哪条断言挂了，断言名字就是检查内容 |

## 四、App 相关

### 4.1 编译/静态检查

| 报错 | 解决 |
|---|---|
| `Target of URI doesn't exist: 'package:xxx/...'` | 依赖没拉或没声明。`flutter pub get`；还不行检查 `pubspec.yaml` |
| `Project with path ':app' could not be found` | `flutter create` 时的 `--project-name` 跟 `pubspec.yaml` 的 `name:` 不一致。必须都是 `money_note`。删掉 `app/android`，用 `flutter create --project-name money_note --platforms android .` 重新生成（平台目录现在已存在，正常不会碰到这个错） |
| `The argument type 'X' can't be assigned to the parameter type 'Y'` | 类型不匹配。看报错的行号，把实际类型和期望类型一起贴给 AI |
| `withOpacity is deprecated` | 换成 `withAlpha(0~255)`。例如 `withOpacity(0.5)` → `withAlpha(128)` |
| `Undefined name 'XxxThemeData'` / `XxxTheme` | Flutter 版本差异。本项目已经规避了这类 API，如果你自己加的代码撞上，改用不设主题、在 widget 上直接写样式 |
| `flutter_lints` 版本冲突 | 把 `pubspec.yaml` 里 `flutter_lints:` 后面改成 `any` |
| `A RenderFlex overflowed by N pixels` | 行/列内容超出屏幕。给 `Row`/`Column` 里的文本包一层 `Expanded` 或 `Flexible` |

### 4.2 界面不动 / 白屏

| 现象 | 原因 | 解决 |
|---|---|---|
| 改了代码界面没变 | 只改了 State 内部状态 | 终端按 `R`（大写）热重启，别按小写 `r` |
| 一片白屏 | 通常是 `build()` 里抛异常了 | 看终端有没有红色异常栈；`flutter run` 的控制台会打出来 |
| 页面不刷新数据 | 没注册 InheritedWidget 依赖 | 页面里必须用 `AppScope.of(context)` 取状态，不能提前存到变量里再跨帧用 |
| `AppScope.of() 找不到 AppScope` | `AppScope` 没套在 `MaterialApp` 外面 | 检查 `main.dart` 的嵌套顺序 |

### 4.3 连不上后端 ⭐ 最高频

**先按这个顺序排查，能解决 95% 的情况：**

**① 后端还活着吗？**

在电脑浏览器打开 <http://localhost:3000/api/health>。
打不开 → 后端挂了，不是 App 的问题。回去 [02](02-跑通后端.md)。

**② 地址对吗？**

| App 跑在哪 | 该用哪个地址 |
|---|---|
| Android 模拟器 | `http://10.0.2.2:3000` ← **不是 localhost** |
| iOS 模拟器 | `http://localhost:3000` |
| 真机 | `http://电脑的局域网IP:3000` |

`10.0.2.2` 是最多人栽的地方。模拟器是一个虚拟设备，它里面的 `localhost` 指模拟器自己。

**③ 真机的话，网络通吗？**

用**手机浏览器**打开 `http://电脑IP:3000/api/health`：

- 打得开 → App 的地址配置错了
- 打不开 → 网络问题（见 ④）

**④ 防火墙 / WiFi**

- 手机和电脑**必须连同一个 WiFi**（手机连的是 4G/5G 就不行）
- Windows 防火墙可能拦了 3000 端口：控制面板 → Windows Defender 防火墙 → 允许应用通过防火墙 → 找到 Node.js → 勾上「专用网络」
- 拿到的是 `172.x` 或 `26.x` 开头的 IP？那是虚拟网卡（WSL / VPN / 虚拟机）的地址，不是真实局域网 IP。挑 `192.168.x.x` 那个

**⑤ 还是不行？手动指定地址**

```bash
flutter run --dart-define=API_BASE_URL=http://192.168.1.7:3000
```

**⑥ 界面顶部显示橙色「正在显示本地缓存」？**

说明网络请求失败了，但缓存有数据所以界面没白。这时去顶部找那条红色错误提示，它会告诉你具体是什么错。

### 4.4 中文乱码

| 现象 | 原因 | 解决 |
|---|---|---|
| 分类名/备注显示成 `????` 或方块 | 解码方式不对 | 本项目已经用 `utf8.decode(res.bodyBytes)` 处理过。如果你改过 `api_client.dart`，确保没退回 `res.body` |
| **只有 `curl` 发中文时乱码** | Windows 终端是 GBK，curl 按 GBK 发的字节 | 这不是服务端问题。用浏览器 / Postman / App 测就正常。服务端返回的中文是好的 |

判断方法：看 `npm run seed` 生成的数据显示正不正常。正常 → 服务端没问题，是客户端编码问题。

### 4.5 Release 版才出的问题 ⭐

| 现象 | 原因 |
|---|---|
| 打包后装到手机上，App 连不上后端 | **INTERNET 权限只在 debug manifest 里**，release 包里没有。项目里已经加好了，先确认 `android/app/src/main/AndroidManifest.xml` 里那行还在。见 [03](03-跑通App.md) 第 4.1 步 |
| 同上，但权限加了还是不行 | 明文 HTTP 被拦。加 `android:usesCleartextTraffic="true"`，或者后端上 HTTPS |
| iOS 真机访问局域网被静默拒绝 | 缺 `NSLocalNetworkUsageDescription`。iOS 14+ 必须有，否则系统不弹窗直接拒 |

> **铁律：调试版能跑 ≠ release 能跑。**
> 每次打包后**一定要真机装一次**验证。

## 五、Gradle / 构建相关

| 报错 | 解决 |
|---|---|
| `Gradle task assembleDebug failed` | `cd app/android && gradlew --stop` 停掉守护进程，再重试 |
| 第一次编译特别久（10 分钟+） | 正常。Gradle 在下载依赖，只有第一次这样 |
| `Could not resolve all dependencies` | 网络问题。检查镜像设置；或者删掉 `app/android/.gradle` 让它重新下 |
| `Execution failed for task ':app:processDebugMainManifest'` | AndroidManifest.xml 改坏了。把改动撤了，对照 [03](03-跑通App.md) 重新改一遍 |
| 突然就编译不过了，什么都没改 | `flutter clean` → `flutter pub get` → 重试 |

## 六、GitHub Actions 相关

| 现象 | 解决 |
|---|---|
| 找不到 Actions 标签页 | 工作流文件必须在 `.github/workflows/` 下，**并且已经 push 到默认分支** |
| 工作流列表里没有「iOS 模拟器构建与录屏」 | 文件名必须是 `.yml` 或 `.yaml`；push 后刷新页面 |
| 按钮是灰的 / 点不了 | 只有带 `workflow_dispatch` 的才能手动触发。本仓库的配置里有，检查 YAML 缩进有没有坏 |
| 构建失败在「flutter analyze」 | 那就是代码有问题。看日志里的具体报错 |
| 构建失败在后端启动 | 看日志最后 `cat /tmp/backend.log` 打出来的内容 |
| 录屏文件下载后打不开 | 说明录屏进程是被 `kill -9` 干掉的，mp4 没写完索引。工作流里用的是 `kill -INT`，别改 |
| 跑一次要多久 | 15～25 分钟。第一次没缓存会更久 |
| 免费额度够吗 | 公开仓库的 Actions **完全免费且不限量**。私有仓库 macOS runner 消耗额度快，容易超 |

## 七、还是解决不了？

**把问题问对，比问得多重要。**

按这个格式整理，再贴给 AI（或者发给我）：

```
【环境】Windows 11 / Flutter 3.x.x / Node 24.15.0
【目标】我想让 App 连上本机后端
【做了】已经确认后端在跑，浏览器能打开 localhost:3000/api/health
【预期】点开 App 能看到数据
【实际】App 顶部显示「连不上 http://10.0.2.2:3000」

完整报错：
<从第一行报错往上多贴 15 行>

相关代码：
<只贴出错的那一个文件的相关片段，别贴整个项目>
```

**「预期 vs 实际」这两行是关键。** 它逼你先想清楚自己到底在期待什么——很多时候写完就发现问题在哪了。

## 八、最容易被忽略的三件事

1. **后端终端有没有一直开着？** 关掉它 App 就没数据了
2. **是不是忘了 `flutter pub get`？** 新增依赖后必须跑
3. **改完 release 配置后重新打包了吗？** `flutter build` 的结果不会自动更新
