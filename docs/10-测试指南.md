# 10 · 测试指南（零基础版）

这篇的目标：**让一个从没写过测试的人，也能证明"我这套东西是好的"。**

不需要懂测试理论，不需要会写断言。照着一个一个点，看结果对不对就行。

---

## 0. 先明白：为什么面试要问测试

招聘方看到你的项目能跑，第一反应是"这是抄的还是自己写的"。
能跑只能证明"跑通了"，**能证明它坏不掉**才说明你真懂。

所以下面的顺序是刻意的：先跑自动测试（证明写的时候就想到了），
再做手工测试（证明每个功能都亲手点过），最后**故意搞破坏**（最有说服力）。

会答题的人在最后一步，不会答题的人在第一步就停了。

---

## 1. 一键测试（最省事，先跑这个）

项目根目录有一个 `run-tests.bat`，**双击它**。

它会按顺序做三件事，每件做完打印一行结论：

```
[1/3] 后端接口测试
[2/3] App 静态检查
[3/3] App 单元测试
```

最后打印一段总结。全部通过会长这样：

```
====================================================
  全部通过 —— 可以截图发给面试官了
====================================================
```

有失败的话，会明确告诉你**是哪一步、哪个文件、第几行**。

> ⚠️ 第一次跑会慢（Flutter 要编译测试代码），后面就快了。

**中文会乱码吗？不会。** 但原因值得说一句，因为它是个真坑：

> `.bat` 文件里**不能写中文**。
> cmd.exe 是按当前代码页（中文 Windows 上是 GBK）**逐字节**解析批处理文件的，
> 而文件存的是 UTF-8 —— 一个中文字符占 3 个字节，cmd 按 GBK 读就是 1.5 个字符，
> "当前读到第几个字节"会算错，结果**下一行会被吃掉开头一两个字**：
>
> ```
> pause        实际执行了  ause
> node_modules 实际执行了  _modules     ← 报"不是内部或外部命令"
> ```
>
> 网上常见的 `chcp 65001` 治不了这个，因为那一行自己也要被解析。
>
> 所以本项目的做法是：`run-tests.bat` **只保留纯 ASCII 的几行**
> （切编码 + 调用 Node），**所有中文都由 `scripts/run-tests.mjs` 打印**——
> Node 写 stdout 用的是确定的 UTF-8，不会错位。
>
> 你以后自己写脚本，记住这一条就够了。

## 2. 手工看结果：三个测试分别是什么

### 2.1 后端接口测试（75 条断言）

```bash
cd backend
npm run smoke
```

**它做了什么**：启动一个临时后端（换一个端口、换一个临时数据库，
绝不碰你的 `data/moneynote.db`），然后像真客户端一样发几十次真实请求，
每次都核对返回值对不对，跑完自己关掉、自己删干净。

期望输出结尾：

```
----------------------------------------------------
  全部通过：75 项断言
----------------------------------------------------
```

**为什么值得跟面试官讲**：它不是"能跑就行"的测试。
里面专门测了这些**只有真踩过坑的人才会想到**的边界：

| 测的东西 | 为什么测它 |
|---|---|
| `2026-02-30` 这种不存在的日期 | 不加校验的话数据库会存进去，之后按月查询就乱了 |
| 金额 `0` / 负数 / 超长小数 | 记账 App 收到 `-5` 元支出，账就废了 |
| `amount: true` / `[5]` / `"12"` | JS 的 `Number(true)` 是 `1`、`Number([5])` 是 `5`。偷懒写成 `Number(...)` 的话，前端传错类型也能建出一条金额变样的记录 |
| **`category: ["餐饮"]`** | `String(['餐饮'])` 就是 `"餐饮"` —— 用 `String()` 做"归一化"会把数组、数字、布尔悄悄转成字符串存下去。得用 `typeof` 判，不是转 |
| `2026-10-31` 往前推一个月的天数 | 10 月 31 天、11 月 30 天，是月份运算的经典陷阱 |
| `from > to` | 前端传反了不能返回 500，要给 400 说清楚 |
| **`offset=99999999999999999999`** | `Number.isInteger(1e20)` 返回 `true`，但这个值 SQLite 的 64 位整数装不下，会抛异常变成 500。**"是不是整数"不够，还得有上界** |
| 删除两次 | 第二次要返回 404，不能静默成功 |
| 服务进程还活着 | 断言再多，进程崩了也是白搭 |
| 日志里没有 `[500]` | 最后兜一道：跑完全程，服务端日志里不该出现任何未捕获异常 |

### 2.2 App 单元测试（53 个）

```bash
cd app
flutter test
```

期望输出：

```
00:00 +53: All tests passed!
```

> 那个 `+53` 就是跑过的测试个数。**只要看到 `All tests passed!` 就是全过**，
> 中间那些一行行的 `+1` `+2` … 是测试名，滚过去就行，不用逐条看。
>
> 四个文件：
> - `test/format_test.dart` —— 月份加减、金额格式化、百分比、日期友好显示
> - `test/net_error_test.dart` —— 把各种网络异常原文归类成一句人话
> - `test/edit_page_date_test.dart` —— 日期选择器能不能打开（见下）
> - `test/api_client_paging_test.dart` —— 拉列表时会不会翻页（见下）

**它测的是什么**：前两个文件测的是 `lib/core/` 里的纯函数——月份加减、
金额格式化、百分比、日期友好显示、网络错误归类。不碰界面，所以跑得飞快（毫秒级）。
后两个分别守住一个**手工很难发现**的 bug：

**一、日期选择器崩掉**（`edit_page_date_test.dart`）

> 日期选择器的可选范围（`firstDate`..`lastDate`）原本是围着**今天**定的
> —— `2020-01-01` 到明年年底。
> 但它的初始值 `initialDate` 来自**当前正在看的那个月**
> （你翻到几月，它就是这个月的 1 号）。
>
> 这两个基准不一样，就必然有一个年份让初始值掉到范围外。
> 翻到 2028 年点「记一笔」→ 点日期 → 内部断言
> `initialDate 2028-06-01 must be on or before lastDate 2027-12-31` 直接失败，
> 调试模式下整个界面挂掉。
>
> **为什么手工很难发现**：在 2026 年（今年）走查功能，一切正常。
> 你得先想到"我把月份翻到两年后再试试" —— 正常验功能的人不会那么干。
>
> 修法是让范围跟着初始值走，于是"初始值一定在范围内"变成一条
> **能推理出来的性质**，而不是碰巧成立。
> 这个测试就是守住这条性质的：故意挑 2028 年、2019 年、跨年前后的月份
> 各试一遍，只要有人把范围改回写死的值，它立刻会红。

**二、列表拉不全**（`api_client_paging_test.dart`）

> 后端一个请求最多返回 1000 条。客户端如果只拉一次就完事，
> 某个月超过 1000 条时会有一屏两个数字对不上：
> 顶部卡片说"1001 笔"（这个数字来自统计接口，是真的），
> 列表却只有 1000 行 —— 而且有一条记录**用户永远看不到**。
>
> **为什么手工很难发现**：种子数据只有 65 条。
> 你得先造出 1000 条以上的数据，才可能碰到它。
>
> 这个测试的做法是不连真后端，直接**伪造出"正好 1001 条"**这种
> 现实里很难摆出来的数据（用 `package:http` 自带的 `MockClient`），
> 然后断言"一条都不能少"。
>
> 顺带说一个测试自己的价值：写这个测试的时候，
> 它当场发现了修复方案里的一个瑕疵 —— 当数据**正好**是 1000 的整数倍时，
> 循环会多打一次注定返回空数组的请求。
> **测试不只验证"对不对"，还会逼出"够不够好"。**

**这里藏着一个真实的 bug 故事，面试必讲**（详见 [08](08-面试准备.md)）：

> 起初写"上个月"是这样算的：`year += (month - 1) ~/ 12`。
> 对 1 月往前推一个月（`month = 1`，`(1-1)/12 = 0`）是对的，
> 但对 `2026-01` 再往前推时，`(0-1) ~/ 12` 在 Dart 里等于 `0` 而不是 `-1`
> —— 因为 `~/` 是**向零取整**，不是向下取整。
> 结果 `2026-01` 往前一个月变成了 `2026-12`，跨年直接算错。
>
> 这个 bug **手工点是点不出来的**——你得正好在 1 月点"上个月"。
> 是写单元测试的时候才炸出来的。这就是"为什么要写测试"最实在的答案。

### 2.3 App 静态检查

```bash
cd app
flutter analyze
```

期望输出：

```
No issues found!
```

或者带一些 `info` 级别的风格提示（**不影响，可以不管**）：

```
info • Prefer const with constant constructors • lib/pages/home_page.dart:88:9
```

判断标准只有一条：

| 看到什么 | 要不要管 |
|---|---|
| `error` | **必须管**，编译都过不去 |
| `warning` | **建议管**，多半是真 bug |
| `info` | 不用管，纯风格 |

> 这份代码现在的状态是 **`No issues found!`** —— 一条提示都没有，
> 连 info 都没有。所以你跑出来应该也是干净的。
>
> 如果冒出来 `dangling_library_doc_comments` 这类 info，别慌，
> 它说的是"文件开头那段 `///` 注释没地方挂"。文件顶部的 `///` 在 Dart 里叫
> **库文档注释**，必须紧跟一个 `library;` 指令才算数。
> `lib/core/format.dart` 和 `lib/core/net_error.dart` 里都有这行，
> 就是为它加的 —— 它不生成任何代码，纯粹给注释一个落点。

## 4. 故意搞破坏 —— 最能加分的一节

**功能正常只能证明你会写，异常处理才能证明你想过。**

下面每条都是"把环境弄坏，看 App 怎么反应"。做完你会对这套代码
有完全不一样的理解，面试时也有真东西可讲。

### 破坏实验 1：把后端关掉

1. 找到跑后端的那个终端，按 `Ctrl + C` 停掉
2. 回到 App，**下拉刷新**（或切一下月份）

**期望**：顶部出现一条红色提示「连不上 http://… 后端没启动或地址填错了」，
**列表里原来的数据还在，没有变白屏**。

**为什么这样设计**：这是"离线优先"。网络挂了不该让用户什么都看不到。
代码在 `lib/state/app_state.dart` 的 `load()`——先读本地缓存渲染出来，
再去请求网络；网络失败**只在顶部挂一条提示，不清空列表**。

> 录屏的时候这一段一定要有，效果最好（见 [05](05-录屏与打包.md) 的最后一幕）。

**恢复**：终端里重新 `npm run dev`，再下拉刷新，红色提示消失。

### 破坏实验 2：把地址填错

```bash
cd app
flutter run --dart-define=API_BASE_URL=http://127.0.0.1:9999
```

**期望**：提示里会**带着你填的这个地址**：
「连不上 http://127.0.0.1:9999，后端没启动或地址填错了」。

**为什么提示里要带地址**：十次"连不上"里有八次是地址填错了。
让人直接看见当前用的是什么地址，比让他去翻代码快得多。

### 破坏实验 3：疯狂连点上个月

连着快速点 10 次「上个月」箭头。

**期望**：最后停在正确的月份上，**不会闪回**到中途某个月份。

**为什么**：每个月的数据是一次网络请求。快速点击会同时发出 10 个请求，
它们**返回顺序是随机的**——第 3 个请求可能比第 10 个晚回来，
一落地就把 10 月的数据覆盖成 8 月的，界面"跳"回去。
代码里的解法是一个自增的请求序号 `_seq`：每个请求发出时记下序号，
回来时如果序号已经不是最新的，**直接丢弃这次结果**。

> 这段代码在 `lib/state/app_state.dart` 第 29 行附近，
> 面试官问"你怎么处理并发"的时候，这就是答案。

### 破坏实验 4：手机开飞行模式

真机或模拟器开飞行模式，然后切月份。

**期望**：和"关掉后端"一样——旧数据还在，顶部有提示，不崩。

### 破坏实验 5：翻到很远的月份再记一笔

**这条是新增的，专门为了守住一个刚修掉的 bug，建议一定做一遍。**

1. 在首页顶部一直点「下个月」的箭头 `›`，**点 20 次以上**（会走到 2028 年）
2. 点右下角「记一笔」
3. 点那一行**日期**

**期望**：日历照常弹出来，能翻能选。

**如果这里崩了 / 界面上弹出一大段红字**，说明日期选择器的范围又被写死了。

> **为什么要翻这么远**：这个 bug 在 2026 年（今年）是看不见的 ——
> 日期选择器的可选范围原本是 `2020` 到"明年年底"，围着**今天**定的；
> 而它的初始值来自**你正在看的那个月**。翻到 2028 年，初始值就掉到范围外了。
>
> 这类 bug 的特点就是**必须"多加一步"才能看见**。面试时讲得出来的，
> 往往是这种"我知道我该试试什么"的判断，而不是"我点了所有按钮"。

### 破坏实验 6：删掉一条记录

点开一条记录 → 右上角垃圾桶 → 弹窗点「删除」。

**期望**：弹窗、删掉、回到首页、那条不见了、**结余数字跟着变了**。

再试一次，这次在弹窗里点「取消」——**应该什么都没发生**。

## 5. 把测试变成面试素材

做完上面这些，你的回答就不再是"我做了个记账 App"了。
面试官问"你怎么保证代码质量"，你可以这样答（照着说就行）：

> 分三层。
>
> **第一层是后端接口测试**，75 条断言，一条命令跑完。
> 它不是只测"正常能不能跑"，重点测的是边界：不存在的日期像 2 月 30 号、
> 金额传 0 或负数、`from` 比 `to` 还大、重复删除。
> 这些都会让数据变脏，而且前端很难防住，只能后端拦。
>
> **第二层是纯函数的单元测试**，跑得飞快。
> 这里抓出来一个真实的 bug：我之前算"上个月"用的是
> `(month - 1) ~/ 12`，Dart 的 `~/` 是向零取整，
> 所以 1 月往前推会算出 12 月，跨年就错了。
> 这个 bug 手工点不出来——你得正好在 1 月点"上个月"。
>
> **第三层是异常场景**。我把后端停掉、把地址填错、疯狂连点月份。
> 关掉后端的时候列表不能变空——先读本地缓存渲染，网络失败了
> 只在顶部挂一条提示。连点月份的时候会有请求乱序返回的问题，
> 我用了个自增序号丢弃过期响应。

**这段话里每一句都对应代码里的一个真实位置。**
面试官追问"在哪一行"，你要能翻出来。

## 6. 出问题了怎么办

| 现象 | 多半是什么 |
|---|---|
| `run-tests.bat` 说找不到 `flutter` | Flutter 没装进 PATH，回 [01](01-环境搭建.md) |
| `flutter test` 卡在 `Resolving dependencies` | 网络问题，见 [01](01-环境搭建.md) 的镜像配置 |
| `npm run smoke` 说端口被占用 | 你的后端还开着，先 `Ctrl + C` 停掉再跑 |
| 界面全中文乱码 | 换 Windows Terminal / VS Code 终端重开 |
| 其它 | 把**完整输出**贴给 AI，看 [09](09-排错速查.md) 的问法 |
