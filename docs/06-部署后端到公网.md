# 06 · 把后端放到公网（这样电脑关机了 App 也能用）

## 这一步解决什么问题

到现在为止，后端是跑在**你自己电脑上**的（`npm start` 那个黑窗口）。
后果就是：

- 电脑一关机 → App 打不开，一直"连不上"
- 电脑睡了 → 同上
- 手机出门用 4G → 连不上家里的局域网，同上
- 把 APK 发给面试官 → **他连不上你家 WiFi，装上去就是个空壳**

把后端搬到一台**别人家、7×24 开着**的服务器上，上面四条全部消失：

| | 电脑上的后端 | 公网上的后端 |
|---|---|---|
| 自己电脑关机能用吗 | ❌ | ✅ |
| 手机用 4G/流量能用吗 | ❌ | ✅ |
| 发给别人能直接用吗 | ❌ | ✅ |
| 要花钱吗 | 0 | **0**（Render 免费档） |
| 要多久 | — | 约 30 分钟 |

**做完这一节，你会得到一个 `https://xxx.onrender.com` 的地址。
这个地址不依赖你的电脑，随时都在。**

---

## 什么时候该做这一步

| 场景 | 需要吗 |
|---|---|
| 只想发邮件给 HR（GitHub 链接 + 录屏） | ❌ 不需要 |
| 对方想实际装个 APK 玩一下 | ✅ **需要**（APK 里的地址是写死的） |
| 想在任何地方打开 App（不在家、关着电脑） | ✅ **需要** |
| 你自己在 iOS 上跑，又不想动 ATS 配置 | ✅ 需要 |
| 想证明"我懂部署" | ✅ 加分 |

**如果你要"电脑关机了还能用"，那就是这一节，没有别的办法。**
（Android 手机想装个能到处用的 APK，也必须先有它。）

---

## 先看：免费服务器到底有哪些，怎么选

你的要求其实是矛盾的：**"7×24 开着"和"免费"是冲突的** —— 机器开着就要耗电、占机房，
所以没有人真的白送。所有"免费"方案的本质都是：**大厂掏钱请你去用它**，
代价是资源少、会休眠、可能随时被收回。

能满足这个项目的，就下面三个：

| 方案 | 花钱 | 电脑关机还能用吗 | 国内访问 | 上手时间 |
|---|---|---|---|---|
| **Render 免费档** | 0 | ✅ | ⚠️ **能通，但慢**（下面有实测） | **30 分钟** |
| **国内轻量服务器** | ¥10/月起（学生机更便宜） | ✅ | ✅ **快** | 1～2 小时（要自己配） |
| 内网穿透（frp / cloudflared） | 0 | ❌ **电脑一关就没了** | ✅ | 30 分钟 |

**第三条不满足你的需求，直接排除。** 它穿透的是"你自己这台电脑"，
电脑关了，隧道那头就没人应答了 —— 和现在没区别。

**所以只有两条路，而它们的取舍很干净：**

- **Render** = 用**速度**换**省事**。30 分钟搞定，但慢。
- **国内服务器** = 用**钱**换**速度**。每月十块钱，快。

**先做 Render。** 因为它是免费的、30 分钟能出结果，
而且做完你才能真正判断"到底够不够快" —— 现在纠结没有意义，测一次就知道了。

### 实测：Render 在国内到底有多慢

这是我今天（2026-10-16）**从本机直接测的**，没有任何加速工具：

| 目标 | 握手（TCP+TLS） | 首字节 |
|---|---|---|
| `*.onrender.com` | 0.5 ～ 2.0 秒 | **2.2 ～ 4.1 秒** |
| `render.com` 官网 | 0.8 秒 | 1.3 秒 |
| `*.github.io` | 0.6 ～ 2.1 秒 | **0.4 ～ 1.4 秒** |

出网 IP 是福建省联通（`ipinfo.io` 查的 `218.106.145.74 / CN / AS4837`），
**没开任何代理**，所以这组数字代表国内普通家用宽带。

**怎么读这组数字：**

- **`onrender.com` 没被墙，能连通。** 这是好消息，网上说"被墙"的多半是特定运营商。
- **但它慢得有点难受**：光是握手就要 2 秒。
- **更要命的是叠加冷启动**：免费档 15 分钟没人访问就休眠，
  下一次请求要唤醒，官方文档写的、以及社区反馈的都是 **30～60 秒**。

**把这两个加起来，就是面试官点开你 APK 的真实体验：**
打开 → 转圈 → **等 30～60 秒** → 出数据。

这个体验本身是能接受的（转圈总比报错好），但你要**知道**它会发生，
并且提前把实例唤醒（见下面"面试前一晚的固定动作"）。

> **网页版反而快。** `github.io` 只要 0.4～1.4 秒，比 `onrender.com` 快一个数量级。
> 所以你完全可以让网页版当门面（[12](12-部署到网页端.md)），
> Render 只在对方真要装 APK 时才需要。

### 那什么时候该换成国内服务器？

出现下面任何一条，就花那十块钱：

- 实测下来你自己都嫌慢（很可能，因为你在国内）
- 面试官/HR 反馈"打不开"或"一直在转"
- 你想让对方打开就能立刻看到东西，而不是等一分钟

**怎么换**：买一台腾讯云/阿里云的**轻量应用服务器**，把 `backend/` 整个目录传上去，
`npm install && npm start`，然后

```bash
flutter build apk --release --split-per-abi ^
  --dart-define=API_BASE_URL=http://你的公网IP:3000
```

**如果你还是学生，先去搜"学生机"，别直接按原价买**（价格活动经常变，以官网为准）：

| 平台 | 大致是什么 | 备注 |
|---|---|---|
| **腾讯云 云+校园** | 轻量 2核2G，大约 **¥75/年** 这个量级 | 要学生认证 |
| **阿里云 高校计划** | 学信网认证后送代金券，有 1核2G ECS **免费用 12 个月** 的活动 | **免费试用的机器不能备案**（用 IP 正好，不影响你） |

> ⚠️ 上面这些价格是**参考值，不是我实测的** —— 这类活动一年变好几轮，
> 网上大量教程写的是旧价格。**以官网当天页面为准。**

> **只跑 IP、不绑域名的话，不需要备案。** 备案是"域名指向国内服务器"才要求的，
> 这是国内方案最容易劝退人的一步，其实用 IP 就绕开了。
>
> ⚠️ 但要把话说全：**用 IP 的话避开 80 和 443 端口**（我们用 3000，正好避开）。
> 这两年云厂商对"未备案域名指向国内机器"的自动检测变严了，
> 所以别去绑一个没备案的域名。用 IP + 3000 端口是最省事的组合。

> ⚠️ 用 IP + HTTP（不是 HTTPS）时，Android 9+ 默认禁止明文流量 ——
> 本项目已经打开 `usesCleartextTraffic`（[03 §4.1](03-跑通App.md)），不用再改。
> 但 **iOS 不行**：iOS 对裸 IP 的限制更严（[03 §4.2](03-跑通App.md)），
> iOS 端要么走 HTTPS，要么老老实实用 Render 那种自带 HTTPS 的地址。

## 方案一：Render（最省事，推荐）

### 0. 先确认你已经推到 GitHub

没做过就先看 [11 上传到 GitHub](11-上传到GitHub.md)。
Render 是从 GitHub 上**拉你的代码**去部署的，所以代码必须先在 GitHub 上。

### 1. 在 Render 上创建服务

1. 打开 <https://render.com>，用 **GitHub 账号直接登录**（不用另外注册）
2. 登录后点 **New → Blueprint**
3. 在列表里选中你的仓库 → 点 **Apply**

> 仓库**根目录**已经有 `render.yaml`，Render 会自己读它。
> 所以你**不用手填**根目录、构建命令、启动命令这些东西——
> 它会自动用 `backend/` 做根目录（配置里的 `rootDir: backend`）、
> `npm install` 构建、`npm start` 启动。
>
> ⚠️ Blueprint 只会自动读**仓库根目录**的 `render.yaml`。放进 `backend/` 里
> 它找不到，而且不会报错，只是列表里看不到这个服务 —— 所以别再把它挪回去。

> **关于 `region: singapore` 这一行**（配置文件里已经写好了）：
> Render 的可选区域是 Oregon / Ohio / Virginia（美国）、Frankfurt（德国）、新加坡，
> 新加坡是离国内最近的一个，所以选了它。
>
> **免费档可以用新加坡**，这一点是查证过的（不是猜的）：
> 官方 Regions 文档列了新加坡、且没有写和套餐的关系；
> 更直接的证据是 Render 自己的状态页 —— 它的组件列表里**有一个就叫
> "Singapore - Web Services - Free Tier"**（免费档的新加坡 Web 服务）。
> 组件是按真实产品建的，存在这个名字就说明这种东西存在。
>
> > ⚠️ 但这不等于"永远有位置"。2026-04-08 那天 Render 因为容量问题
> > **临时关闭过新加坡的免费服务**（当天恢复）。所以真遇到创建失败，
> > 换个时间再试，或者先部署到默认区域跑通再说。
>
> 部署完在 Render 后台看一眼服务显示的是哪个区域，确认它真的生效了 ——
> 配置文件里写了不等于平台采纳了，这类"写了但没生效"的配置最难发现。

等 3～5 分钟（页面上会滚动构建日志），拿到一个地址：

```
https://moneynote-api-xxxx.onrender.com
```

**把它抄下来**，后面每一步都要用。

### 2. 验证它真的活着

浏览器直接打开（把地址换成你的）：

```
https://moneynote-api-xxxx.onrender.com/api/health
```

看到 `{"ok":true,...}` 就成了。

再打开这个看一眼数据：

```
https://moneynote-api-xxxx.onrender.com/api/stats?month=2026-10
```

**应该能看到一堆数字，而不是空的。** 为什么空不了，见下面第 3 节。

### 3. 让 App 连上它

```bash
cd C:\Users\chenj\eclipse-workspace\demo0\app

flutter build apk --release --split-per-abi ^
  --dart-define=API_BASE_URL=https://moneynote-api-xxxx.onrender.com
```

> `^` 是 Windows CMD 的换行符。用 PowerShell 或 Git Bash 的话换成 `` ` `` 或 `\`，
> 或者干脆写成一行。

装到手机上，**关掉电脑试试**——这才是这一步的验收标准。

### 4. ✅ 验收：关电脑实测

这是整节的重点。**没做这一步，等于没做这一节。**

1. 手机装上第 3 步打出来的 APK
2. **把电脑彻底关机**（或者至少退出 `npm start` 那个窗口）
3. 手机**断开 WiFi，只用流量**（这一步是为了证明它真没走你家局域网）
4. 打开 App

**看到数据 = 成功。** 你现在有一个关掉电脑还能用的 App 了。

如果还是连不上：
- 先确认第 2 步的 `/api/health` 在**手机浏览器**里也打得开
- 打得开 → 是 APK 里的地址不对，检查 `--dart-define` 有没有写错
- 打不开 → 是 Render 那边的问题，去 Render 的日志页看

> iOS 那边**什么都不用改**——HTTPS 本来就在 ATS 白名单里，
> [03 §4.2](03-跑通App.md) 那两段 `Info.plist` 配置可以不加。

## ⚠️ 必须知道的三个坑

### 坑 1：免费档的磁盘是临时的 —— 已经替你修好了

Render 官方文档原话是
"Whenever a service spins down, **any changes to its local filesystem are lost**"
（<https://render.com/docs/free>）。

**注意它说的是 "spins down"（休眠），不只是"重新部署"。**
而免费实例 15 分钟没人访问就会休眠 —— 也就是说，
**你的数据库大约每 15 分钟就被清一次**，比"每次部署才清"严重得多。

你的 `data/moneynote.db` 就在这个文件系统里。

**后果本来会是**：面试官点开 App，看到的是一个**空账本**，
还以为你的项目是坏的——这比报错更糟，因为他不会来问你。

**已经处理掉了。** 仓库根目录的 `render.yaml` 里设了：

```yaml
- key: AUTO_SEED
  value: '1'
```

服务每次启动时检查一遍：**库是空的就自动灌一批演示数据**（[src/server.js](../backend/src/server.js) 的 `seedIfEmpty`）。
所以无论 Render 怎么重启，App 打开永远是有内容的。

**关键的一点**：它**只在空库时**动手，不会清掉已有数据。
（`npm run seed` 那个脚本是**先清空再写入**的，这两者不是一回事——
拿它来做自动补数据，等于每次重启都把你记的账清空一次。这个区别写在 `seedIfEmpty` 的注释里了。）

> **想更进一步**（可选，演示不需要）：临时磁盘终究存不住**用户真正记的账**。
> 要真持久化，得换成 Render 的付费 Disk（$7/月起），
> 或者换成托管数据库（Neon / Supabase 的免费 Postgres）。
> 好消息是 SQL 全在 `backend/src/repo.js` 这一个文件里，
> 换数据库只改这一层——这就是分层的意义。

### 坑 2：免费实例会休眠

15 分钟没请求就睡。下次请求要等 **30～60 秒**才醒。

**后果**：对方一打开 App，转圈一分钟，以为你的 App 是坏的。

**怎么办**：

- **演示/录屏前，先自己打开一次** `https://你的地址/api/health` 把它唤醒，等它返回再开始
- 面试前 5 分钟做一次这个动作，成本很低，能省掉一次尴尬
- 也可以给 Render 加个定时 ping，但免费额度有限，容易被判定滥用，不推荐

### 坑 3：`CORS_ORIGIN`（做网页版才需要）

如果之后要做 [12 那个网页版](12-部署到网页端.md)，在 Render 的环境变量里加：

```
CORS_ORIGIN=https://你的网页版域名
```

本地开发和**手机 App 都不用管**——Flutter 原生 App 不走浏览器的 CORS。

## 方案二：别的平台

### 先说一条决定性的约束：这个后端要写**本地文件**

`backend/src/db.js` 把数据库放在 `data/moneynote.db`，就是一个**文件**。
它要活下来，宿主必须给它一块**持久的本地磁盘**。

这条约束很硬，它一下就砍掉了大部分"免费"托管：

| 类型 | 能不能跑我们这套 | 例子 |
|---|---|---|
| 无服务器 / 边缘函数 | ❌ 没有常驻进程，也没有本地文件 | Vercel、Netlify、EdgeOne Makers、阿里云 ESA |
| 容器托管但磁盘是临时的 | ⚠️ 能跑，但数据库每次重启就没 | **Render 免费档**（靠 `AUTO_SEED` 兜住） |
| 真正的虚拟机 / VPS | ✅ 持久磁盘，正合适 | 国内轻量服务器、华为开发者空间 |
| 托管数据库 + 无状态后端 | ✅ 但要改代码 | Neon / Supabase（Postgres） |

**所以"又免费、又国内能访问、又能存住本地 SQLite"这三个条件同时满足的，
基本只剩"国内的学生机 / 免费试用虚拟机"这一类。** 前面推荐的 Render 之所以能用，
是因为我们用 `AUTO_SEED` 把"数据库会丢"这件事接住了 —— 它换的是"演示够用"。

### 其他平台的现状

| 平台 | 现在还能免费用吗 | 说明 |
|---|---|---|
| **Fly.io** | ❌ 免费档 **2024 年 10 月就取消了** | 新用户只有试用（约 2 个 VM 小时 / 7 天），之后要绑卡 |
| **Railway** | ❌ 只有一次性 $5 试用额度 | 用完转 $5/月的 Hobby |
| **Koyeb** | ❌ **2026 年 2 月**起对新用户关闭免费档 | 新注册默认 Pro（$29/月） |
| **Zeabur** | ⚠️ 免费共享集群从 **2026-03-15** 起要 Dev 套餐（$5/月） | 已有服务继续跑，**新项目要付费** |
| **Vercel / Netlify** | 免费 | ❌ 只跑 Serverless 函数，没有本地文件 |
| **腾讯云 EdgeOne / 阿里云 ESA** | 免费额度不小 | ❌ 同样是边缘函数，**没有常驻进程**，我们这套跑不了 |
| **华为开发者空间** | 有免费主机额度 | ✅ 是真虚拟机，能跑 |
| **国内轻量服务器 / 学生机** | ❌ 但很便宜 | ✅ 最省心的一条 |

> ⚠️ **这张表里的政策我大部分没能对到官网原文**（见下面"哪些查证过"）。
> 云平台的免费额度是"随时会变"的东西，网上大量教程写的还是旧政策 ——
> **包括我这张表，用之前都请以官网当天页面为准。**
> 表里唯一逐条核对过官方文档的是 Render。

**为什么特意列这些"已经不能免费用了"的平台**：因为搜"免费部署 Node"，
排在前面的文章十有八九还在推荐 Fly.io 和 Railway。
**照着做会浪费你一晚上**，然后卡在绑卡那一步 —— 而你不会知道是文章过期了，
多半会以为是自己哪步做错了。

### 用 Dockerfile 部署到任意平台

仓库里有 `backend/Dockerfile`，它是给"自己的服务器 / 云托管平台"用的。

> ⚠️ **这条路我没有验证过**：这台机器上**没装 Docker**
> （`which docker` 找不到），所以这个镜像**从来没有真正构建过**。
> Dockerfile 本身逻辑很简单，但"简单"不等于"验证过"——
> 你如果走这条路，构建报错是可能的，把报错贴给 AI 就行。

```bash
cd backend
docker build -t moneynote-api .

# ⚠️ 注意这里比原来的文档多了两个参数，都是必需的：
docker run -p 3000:3000 \
  -e AUTO_SEED=1 \
  -v moneynote-data:/app/data \
  moneynote-api
```

**两个参数为什么必需：**

- **`-e AUTO_SEED=1`** —— 不然容器里是个空库，App 打开什么都没有。
  （和 Render 那边是同一个开关。）
- **`-v moneynote-data:/app/data`** —— 把数据库放到一个 **volume** 里。
  不加的话，数据只活在容器内部，**容器一删就全没了**。
  加了之后，`docker run` 第二次启动还是同一份数据，
  `AUTO_SEED` 也会自动跳过（因为库不空了）。

**更省事的写法（VPS 一键起）**：仓库里有 `backend/docker-compose.yml`，
上面这些参数都已经写好，不用手敲：

```bash
cd backend
docker compose up -d          # 第一次会自动构建
docker compose logs -f        # 看日志，Ctrl+C 退出但不影响服务
docker compose down           # 停掉（数据还在 volume 里）
```

端口 `3000`、`AUTO_SEED=1`、`./data:/app/data` 持久化、健康检查都在那个文件里。
想改端口就改 `ports:` 左边那个数字（右边 `3000` 是容器内的，不要动）。

> **这一点比 Render 免费档强**：Render 免费档没有持久磁盘，
> Docker + volume 是有持久化的。代价是得自己找一台机器。

### 顺带说一下 `.dockerignore`

仓库里有 `backend/.dockerignore`，它不是可选项，理由写在文件开头。简单说三件事：

| 不排除它会怎样 | 后果 |
|---|---|
| `node_modules/` 被拷进去 | **覆盖**掉镜像里 `npm ci` 装好的那份依赖。本机是 Windows、镜像是 Alpine，等于拿另一套平台的产物去跑。现在依赖是纯 JS 所以多半没事，**以后引入任何原生模块就炸**，而且报错指向你的代码、不指向这个原因 |
| `data/` 被拷进去 | 你本机那个 `moneynote.db` 被**烤进镜像**，谁拿到镜像就拿到你的账本。也正因为这样，上面才改用 volume |
| `.env` 被拷进去 | **最要命的一条**：镜像的每一层都能被别人 `docker history` 翻出来，写进去的密钥等于公开 |

## 做完了检查一遍

- [ ] `https://xxx.onrender.com/api/health` 在**手机浏览器**里能打开
- [ ] `https://xxx.onrender.com/api/stats?month=本月` 能看到数字，不是空的
- [ ] APK 装到手机上，**把电脑关机、手机切到流量**，App 仍能拉到数据
- [ ] 在 App 里记一笔，**马上**刷新，这笔还在（说明"写"也通了，不只是"读"）

> 最后一条容易忽略：它验证的是"写"也通了，而不只是"读"。
>
> ⚠️ **必须"马上"刷新。** 免费档休眠时会丢本地文件（坑 1），
> 所以如果你记完一笔、隔了半小时再回来，那笔账**大概率不在了** ——
> 这不是你的操作有问题，是免费档的性质。
> **验收时别被它误导**，以为写入失败了。

## 面试前一晚的固定动作

免费实例会休眠，所以**演示前一定要先唤醒**：

1. 手机/电脑浏览器打开 `https://xxx.onrender.com/api/health`，等它返回（第一次可能要 30～60 秒）

## 这一章里的话，哪些查证过、哪些没有

云平台的信息**过期得特别快**，所以把每条结论的来源摊开写，你自己判断：

| 结论 | 怎么来的 | 可信度 |
|---|---|---|
| 免费档会休眠、丢文件、750 小时/月 | 官方文档 <https://render.com/docs/free> 原文 | ✅ 逐条核对 |
| 免费档能用新加坡区域 | 官方 Regions 文档 + Render 状态页里真的有 "Singapore - Web Services - Free Tier" 这个组件 | ✅ 强证据 |
| `onrender.com` 在国内的实际延迟 | **本机实测**（福建联通，无代理，见上文表格） | ✅ 实测 |
| 免费档冷启动 30～60 秒 | 官方文档 + 社区反馈，**不是我实测的** | ⚠️ 未实测 |
| Fly.io / Railway / Koyeb / Zeabur 已无免费档 | **二手来源**（博客、论坛），没能对到官网原文 | ⚠️ 可能不准 |
| 学生机价格 | 二手来源，这类活动一年变好几轮 | ⚠️ 别当真，看官网 |
| Docker 镜像能不能构建成功 | 本机没装 Docker，**从没构建过** | ❌ 没验证 |
| iOS / 安卓 / Web 三个工作流能不能跑通 | 本机没有 GitHub Actions 环境，**从没真跑过** | ❌ 没验证 |

> 最后两行才是重点。**"没验证"不等于"有问题"，但也绝不等于"没问题"** ——
> 它只是"我不知道"。这个项目里所有没验证的东西都会像这样列出来，
> 而不是含糊地写成"应该可以"。
